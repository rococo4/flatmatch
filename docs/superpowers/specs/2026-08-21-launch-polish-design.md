## Решения

| Вопрос | Решение |
|---|---|
| Трекинг источника | `t.me/<бот>?startapp=src_<код>`; код `[a-z0-9_]{1,32}`; фронт после первого `/me` шлёт `POST /api/v1/me/source {source}`; сервер пишет `users.source` ТОЛЬКО если NULL (первое касание); `src_*` никуда не ведёт (обычный вход) |
| Блок | `POST /api/v1/people/{id}/block` → строка в `blocks` (идемпотентно); невидимость обоюдная и немедленная — через существующий `visible_people`; разблокировки в MVP нет (ни API, ни UI) |
| Жалоба | Тем же ботом в MODERATION_CHAT: `POST /api/v1/people/{id}/report {reason, context}` → `reports` + карточка модератору с кнопками `[Забанить] [Пропустить]` (колбэк-субъект `r`); повтор той же пары → 200 без новой карточки; жалоба НЕ блокирует автоматически — после отправки UI предлагает «Заблокировать» отдельной кнопкой |
| Причины жалобы | чипы: `spam` «Спам/реклама», `scam` «Мошенничество», `abuse` «Оскорбления/угрозы», `other` «Другое» |
| Бан | колбэк «Забанить» → `users.status='banned'` (идемпотентно; уже забаненный — «уже обработано»), его pending-пуши гасятся (`FailAllPending`), карточка получает метку вердикта как у модерации; «Пропустить» → `reports.resolved_at` |
| Пустая лента зоны | когда в выдаче нет ни точек, ни людей в промо: блок «Пусто — растём из района в район» + существующее промо «подпишись первым» + список «Где уже ищут» — топ-5 зон по числу видимых ищущих (`GET /api/v1/zones/top`), тап → форма просмотра с этой зоной |
| Прочие пустые | «Тебя лайкнули»: «Пока никто не лайкнул — тебя видят в пулах, когда есть сохранённый поиск»; «Мои мэтчи»: «Мэтчей пока нет — ответный лайк на входящий даёт первый»; пул квартиры без людей и зонный пул — уже есть |
| Диплинк «к себе» | `point_<id>` у intent_home открывает отдельный экран с той же карточкой, что в ленте (лицо, мини-карточка комнаты, «Хочу эту комнату»/«✓ У вас мэтч»); кнопка «Открыть» у пинга комнаты ведёт туда же вместо «Мои поиски» |
| Paused-карточка | у не-участника вместо «в пуле N — увидишь после входа» без кнопки — строка «в пуле N · вход закрыт, пока квартиру не подтвердят» |
| Каналы парсера, волна 2 | +`keystomoscow`, +`lvngrm_msk` (из ресёрча), только если t.me/s отдаёт превью на момент правки — проверяется руками один раз, конфиг `PARSER_CHANNELS` по умолчанию |
| Деплой | `scripts/deploy.sh`: rsync репо на сервер (исключения как у контроллера) + `docker compose up -d --build` + `docker image prune -f`; `scripts/backup.sh` на сервере: `pg_dump` в `/opt/flatmatch/backups/`, хранить 7 дней, cron ежедневно 04:00 |

## 1. Схема — миграция 0010_launch.sql

```sql
ALTER TABLE users ADD COLUMN source text NULL;

CREATE TABLE reports (
    id          uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    reporter_id uuid NOT NULL REFERENCES users (id),
    target_id   uuid NOT NULL REFERENCES users (id),
    reason      text NOT NULL CHECK (reason IN ('spam', 'scam', 'abuse', 'other')),
    context_key text NULL,
    created_at  timestamptz NOT NULL DEFAULT now(),
    resolved_at timestamptz NULL,
    verdict     text NULL CHECK (verdict IN ('banned', 'skipped')),
    UNIQUE (reporter_id, target_id)
);
```

`blocks` уже есть (0002) и уже учтена в `visible_people` — миграции не нужно.

## 2. API

- `POST /api/v1/me/source` `{"source": "hsetndr"}` → 204; код валидируется
  `^[a-z0-9_]{1,32}$` (400 `invalid_field` иначе); `UPDATE users SET source = $2
  WHERE id = $1 AND source IS NULL` — повтор с другим кодом молча игнорируется.
- `POST /api/v1/people/{id}/block` → 204; 404 если `id` = себе или пользователя
  нет; `INSERT … ON CONFLICT DO NOTHING`. После блока профиль цели отвечает 404
  как невидимый (visible_people уже так работает) — фронт возвращается назад.
- `POST /api/v1/people/{id}/report` `{"reason": "scam", "context": {"zone_id":
  …|"point_id": …|"match_id": …}}` → 204; валидация reason; контекст
  опционален, хранится как `context_key` строкой `zone:<id>` / `point:<id>` /
  `match:<id>`; `ON CONFLICT (reporter_id, target_id) DO NOTHING` → карточка
  модератору шлётся только при реальной вставке.
- `GET /api/v1/zones/top?limit=5` → `{"zones": [{"id","name","name_in","people"}]}` —
  зоны справочника, отсортированные по числу ЛЮДЕЙ с активным поиском,
  пересекающим зону, видимых смотрящему (`visible_people`), только `people > 0`.
  Реализация: активные поиски видимых людей → их зоны → разворачиваем через
  `dir.Intersecting` на станционные зоны → считаем уникальных людей по зоне
  справочника (район/ветка/станция). Лимит ≤ 20.

Ошибки и коды — по образцу соседних хендлеров (`httpx.Error`, русские
сообщения в errors.go).

## 3. Модерация — жалобы

Сервис `moderation`: `ReportFiled(ctx, report, reporter, target entity.User)`
→ `send(subjectReport, report.ID, target.PhotoKey, caption, [[Забанить
mod:r:ban:<id>] [Пропустить mod:r:skip:<id>]])`. Подпись:

```
Жалоба: {reporter.Name} → {target.Name} ({target.Age}) · {reason label}
Контекст: {пул Хамовников | квартира у метро Сокол | мэтч}
О себе цели: {about или «—»}
```

Колбэки: `mod:r:ban:<report_id>` → если report уже `resolved_at` → «уже
обработано»; если цель `banned` → «уже забанен»; иначе `users.status='banned'`,
`FailAllPending(target)`, `reports.verdict='banned', resolved_at=now()` →
метка «✓ Забанен». `mod:r:skip:<id>` → `verdict='skipped'` → «✓ Пропущено».
`/queue` досылает и нерешённые жалобы.

Забаненный: уже сегодня невидим везде (visible_people `status='active'`),
пуши ему не пишутся (Emit фильтрует по banned в queue), вход в приложение
отвечает `ErrBanned` (users.EnsureByTelegramID) — фронт показывает экран
«Доступ закрыт» (проверить, что он есть; если нет — добавить простую
заглушку с текстом «Аккаунт заблокирован»).

## 4. Фронт

- **Стартовый параметр**: `parseStartParam` понимает `src_<код>` →
  `{kind:'source', code}`; оболочка после готового `/me` шлёт
  `postSource(code)` best-effort и открывает обычный вход. Комбинаций
  параметров нет (startapp — одна строка); `src_` приоритетнее ничего не
  значит — просто ещё один вид.
- **Профиль человека**: под контентом — тихая строка действий «Пожаловаться ·
  Заблокировать». Блок: шторка «Заблокировать {имя}? Вы перестанете видеть
  друг друга везде — в пулах, лайках и пушах. Отменить нельзя.» → «Заблокировать»
  (красная) → API → назад, списки перечитываются. Жалоба: шторка с чипами
  причин + «Отправить»; после — «Спасибо, разберёмся» + кнопка «Заблокировать
  {имя}» (та же шторка) и «Готово».
- **Пустая лента зоны** (`feed.data.points` пусто И промо `people == 0`):
  блок «Пусто — растём из района в район» + промо как есть + «Где уже ищут»
  (топ-5 из `/zones/top`, строка «{name} · {people}», тап → `openLookForm`
  с этой зоной). Если топ пуст (совсем никого) — только промо.
- **Тебя лайкнули / Мои мэтчи** — тексты пустых состояний из таблицы.
- **Экран «к себе»** (`HomePointView`): по `point_<id>` с `type=intent_home`
  — та же карточка, что в ленте (вынести карточку «к себе» из FeedScreen в
  компонент и переиспользовать), кнопка «Хочу эту комнату» с тем же потоком
  лайка, что в ленте; «✓ У вас мэтч» при мэтче; для автора — без кнопки.
  Пуш `point_ping` для intent_home: кнопка «Открыть» → `point_<id>`.
- **Paused-карточка** не-участнику: строка «в пуле N · вход закрыт, пока
  квартиру не подтвердят».

## 5. Скрипты

- `scripts/deploy.sh [host]`: хост по умолчанию `flatmatch` (alias из
  ~/.ssh/config); `rsync -az --delete` с исключениями (`.git node_modules .venv
  .dev api/.data web/dist .superpowers .env *.png .claude web/.env.local
  __pycache__ .pytest_cache`) в `/opt/flatmatch`; затем по ssh `docker compose
  up -d --build && docker image prune -f`; печатает `docker compose ps`.
  `.env` на сервере скрипт НЕ трогает.
- `scripts/backup.sh` (кладётся на сервер тем же rsync): `docker compose exec
  -T postgres pg_dump -U $POSTGRES_USER $POSTGRES_DB | gzip >
  backups/flatmatch-$(date +%F).sql.gz`; удаление старше 7 дней; cron
  `0 4 * * *` — ставится контроллером один раз.

## 6. Тесты

- Go: usersrepo `SetSourceIfEmpty` (первое касание побеждает); peoplerepo/
  usersrepo `Block` идемпотентен и профиль после блока → 404 через
  visible_people (интеграционно на тестовой БД); reports: вставка, дубль без
  карточки; moderation: ban-колбэк (идемпотентность, забаненный — no-op,
  метки), skip; zones/top — счёт уникальных людей по пересечению зон
  (район считает людей со станций внутри), невидимые не считаются;
  хендлеры — коды и валидация.
- Фронт: `tsc -b`, lint, build.
- Приёмка на проде (после DNS): ссылка с `startapp=src_test` → в users.source
  'test'; блок Дева → он исчезает из пула; жалоба → карточка в модер-чат →
  «Пропустить»/«Забанить» на тестовом сиде; пустая зона показывает топ-5;
  диплинк на «к себе» открывает карточку.
