# Парсер каналов и досыпка (§12 шаг 7b) — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Задачи трекаются чекбоксами.

**Goal:** Сервис parser: поллинг t.me/s пяти каналов аренды → channel_posts → LLM-структуризация (Sonnet 5) → точки source='tg_channel' в ленте с фото; гашение по удалённому посту; досыпка CLI source='manual'.

**Architecture:** Python-сервис, с бэком только через БД (§10); сырьё в channel_posts (миграция в api/migrations); узкий модуль fetch (HTTP t.me/s + embed) как шов под MTProto. Спека — `docs/superpowers/specs/2026-08-21-parser-design.md` (истина при конфликте с планом; CLAUDE.md на диске — истина продукта; снапшот CLAUDE.md в контексте сабагента может быть устаревшим).

**Tech Stack:** Python 3.13, httpx, beautifulsoup4, psycopg[binary], anthropic (>=1.x), pytest; Go-сторона — только миграция 0009 и compose/.env.example.

**Spec:** docs/superpowers/specs/2026-08-21-parser-design.md

## Global Constraints

- Правило «без комментариев» действует ТОЛЬКО на Go и SQL (миграция 0009 — без комментариев, кроме `-- +goose`). Python — комментарии допустимы, скупо, по-русски, в стиле существующего parser/main.py. Русская микрокопия/тексты — дословно из спеки.
- Python-окружение: `cd parser && python3 -m venv .venv && .venv/bin/pip install -r requirements.txt -r requirements-dev.txt` (dev: pytest). Тесты: `cd parser && .venv/bin/python -m pytest -q`. Тесты с БД используют `TEST_DATABASE_URL='postgres://flatmatch:flatmatch@localhost:5432/flatmatch?sslmode=disable'`, скипаются без переменной; чистят ТОЛЬКО свои строки (channel_posts: свои каналы-неймспейсы `test-*`; points: свой zone_id `s-test-parser` или удаление по RETURNING id) и не полагаются на пустоту таблиц. Строку users tg_id=188993596 не трогать.
- Go-верификация (для задач, трогающих api/): `cd api && gofmt -l . && go build ./... && go vet ./... && TEST_DATABASE_URL='postgres://flatmatch:flatmatch@localhost:5432/flatmatch?sslmode=disable' go test ./...`. Применение миграции к дев-БД: `cd api && go run github.com/pressly/goose/v3/cmd/goose@latest -dir migrations postgres "$TEST_DATABASE_URL" up` (версию goose взять из go.mod, если @latest не совпадёт).
- Живые HTTP-запросы к t.me в тестах ЗАПРЕЩЕНЫ (фикстуры в parser/tests/fixtures/); один живой прогон руками — только там, где задача явно велит (верификация embed).
- Секрет `ANTHROPIC_API_KEY` может отсутствовать в .env до приёмки — код обязан падать понятной ошибкой только при реальном вызове LLM, тесты мокают клиент.
- Коммиты в main (короткое русское сообщение + trailer `Co-Authored-By: Claude Fable 5 <noreply@anthropic.com>`), без push.

```python
    restrictions: list[str]; move_in: date | None; listing_url: str | None

    #   system=[{"type":"text","text":SYSTEM_PROMPT+"\nСтанции:\n"+...,"cache_control":{"type":"ephemeral"}}],

    #   output_config={"format":{"type":"json_schema","schema":EXTRACT_SCHEMA}})

# pipeline.py

```
Правила process_post — по спеке §3 (шаги 3–9, кроме фото — фото Task 3, пока `photo_keys='{}'`): kind≠rent_flat → skipped с причиной=kind (rent_room → 'room', wanted → 'wanted', roommate → 'roommate', other → 'other'); станция не в словаре → 'no_zone'; цена вне 20000..300000 или null → 'no_price'; rooms/deposit/restrictions вне границ → 'bad_fields'; url_norm = normalize_listing_url(listing_url) или `https://t.me/<channel>/<message_id>`; SELECT живой точки по url_norm → 'dup' (запомнить point_id); INSERT points (в транзакции с UPDATE channel_posts; IntegrityError уникального индекса → 'dup'); possible_dup-эвристика по (zone_id, price_total, rooms) живых tg_channel ≤7 дней. Ошибка LLM после повтора → status='error', llm=null, продолжить со следующим постом.
Системный промпт — русский, в нём дословно правила из спеки §3 (total-цена, нижняя граница диапазона, одна станция из списка).
