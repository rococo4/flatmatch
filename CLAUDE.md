# FlatMatch — спека продукта и техконтекст (v2, модель «поиски-подписки»)

Этот файл — единственный источник правды по продукту. Все правила ниже — финальные.
Если реализация конфликтует со спекой — спека права. Ничего из §9 «Вырезано»
не реализовывать, даже если «дёшево добавить».

ВАЖНО: в ранних версиях продукта существовала сущность «заявка» (intent) —
пользовательская точка сбора «ищу со-съёмщика» с автором. Она ОТМЕНЕНА и заменена
моделью поисков-подписок (§2–3). Если где-то встретишь след заявок — это ошибка.

## 1. Что это

Telegram Mini App для поиска со-съёмщика квартиры. Рынок: Москва целиком, без
ограничения по районам. Аудитория — все, кто ищет со-съёмщика; продукт не
студенческий: студенты — приоритетный сегмент посева (август–сентябрь) и
получают бейдж вуза, но никаких гейтов по аудитории нет.

Позиционирование: **не агрегатор квартир, а поиск людей.** «Квартиру найдёшь где
угодно — мы найдём того, с кем её снимать». Метрика успеха — мэтч, дошедший до
совместного поиска/заселения (поиск, закрытый с причиной «нашёл»).

## 2. Ядро механики

Две параллельные системы, сходящиеся в одном месте (профиль → дорогой лайк → мэтч):

### 2.1 Поиски и зонные пулы (люди ↔ люди)

**Поиск (search)** — подписка пользователя на параметры: одна зона из справочника
(район / станция / ветка метро) + бюджет-вилка «с человека» (от опционально — до)
+ опционально: комнатность-вилка, месяц заезда, срок (полгода+/год+/бессрочно),
чипы «что уже есть» (мебель/техника). До 3 активных поисков на человека —
единственный лимит; зоны поисков МОГУТ пересекаться («Хамовники» + «красная
ветка» — два честных разных намерения с разными бюджетами, запрещать их
пересечение значило бы, что ветка блокирует все районы вдоль себя). В пуле
человек при этом один раз (см. §2.1, лучший вердикт). Точный дубль зоны сервер
тоже не запрещает: UI сам уводит от него — промо-блок сохранённой зоны
переключается в «Ты в пуле», кнопки сохранить больше нет.
Поиск — снапшот фильтров ленты в момент подписки (см. §6), отдельной формы нет.

Набор фильтров ЗАФИКСИРОВАН (по ресерчу практик flatshare-продуктов), не
расширять: зона (граница пула), бюджет-вилка «с человека», комнатность,
месяц заезда, срок. Пол — серверное правило видимости (§4), в UI фильтром
не является. Курение, животные и прочие привычки анкеты — НЕ фильтры, а
сигналы сортировки и вердикт-чипы (персональные жёсткие дил-брейкеры —
§9, отложено до плотных пулов). Фильтров по хобби, интересам, «типу
личности» не существует и не будет — не предсказывают совместимость,
схлопывают выдачу.
Поиск не публикуется как карточка — он включает человека в зонные пулы и питает
мэтчинг и пуши.

**Зонный пул** — вычисляемое множество: все люди с активным поиском, чья зона
пересекается с зоной пула. НЕ хранится как сущность, нет владельца, нет
«создания» и «входа»: создал поиск → автоматически виден во всех пулах,
чьи зоны пересекают твою; закрыл поиск → исчез. Пересечение зон — по справочнику
(поиск «Сокол» виден в пуле «оранжевая ветка», т.к. станция Сокол на ней).

Внутри пула — персональное ранжирование под поиск смотрящего, тремя секциями:
«Совпали по всем параметрам» / «Пересекаются частично» / «Не совпали» (видны,
приглушены, свёрнуты после первого). Совпадение = ПЕРЕСЕЧЕНИЕ вилок, не
равенство фильтров («35–45» и «40–55» совпали). NULL-параметр = «неважно»,
совпадает со всем. Формула секций: жёсткие параметры — цена и заезд, мягкие —
комнатность и срок; «полностью» = пересеклись все указанные обоими параметры,
«частично» = пересеклись цена ИЛИ заезд, но не всё, «не совпали» = ни цена,
ни заезд. У каждого человека — чипы его параметров с вердиктом против твоих:
зелёный ✓ (пересеклись), жёлтый «краем» (границы касаются), серый (не
пересеклись / «не указана»). Жёсткая граница пула — только зона; всё
остальное — сортировка и пометки, НЕ отсечка. Пул виден ТОЛЬКО со своим
активным поиском, пересекающим его зону (правило «мы увиделись», §2.3) —
анонимного просмотра списка людей нет; тизер зоны для неподписанных — промо-блок
ленты (счётчик + аватарки), он не гейтится. Людей, с которыми у смотрящего уже
есть мэтч, пул и счётчики не показывают (вы уже нашли друг друга — это шум);
фильтр стоит в выборках discovery, НЕ в visible_people: пара остаётся видимой
друг другу в мэтче и его деталях.

### 2.2 Точки с квартирами (объект/предложение → пул лайкнувших)

Два типа точек (points), у обоих пул = записи лайков:
1. **Квартира с рынка** (`flat`) — внешний объект: ссылка с Авито/Циан + поля,
   пост из ТГ-канала или ручная досыпка. Обезличена: created_by — только
   provenance/лимиты/модерация, в UI не показывается, владельца нет.
2. **«Сосед к себе»** (`intent_home`) — у человека есть конкретное жильё и
   нужен со-съёмщик под него. ДВЕ СТАДИИ (поле stage): `live` — уже живёт в
   квартире, бейдж «живёт здесь»; `moving_in` — договорился с собственником и
   заезжает, бейдж «заезжает · ищет со-съёмщика со старта», дата заезда
   обязательна. Гейт формы: «уже живу здесь» / «договорился и заезжаю» /
   иначе → не наш кейс (для сдачи — классифайды). Личность автора — витрина
   (единственный тип карточки с лицом), + мини-карточка жилья: метро, ЦЕНА
   ДОЛИ въезжающего, фото (до 10; для `moving_in` — фото из квартиры, не
   скрин объявления; первое — обложка), изолированность, депозит, опционально — ограничения
   квартиры чипами («нельзя с животными», «хозяин против пар», «курить
   нельзя»): показывать ДО отклика, чтобы не жечь дорогой лайк впустую.
   Точка смертна вместе с
   предложением автора (TTL, пауза по молчанию после мэтча). Лимиты по
   стадиям: `live` — строго 1 (факт жизни), `moving_in` — до 2 (честный
   кейс «держу запасной вариант»), суммарно ≤2 активных «к себе»; слот
   поисков НЕ занимает (поиски — независимые ≤3). При двух активных
   `moving_in` карточки честно показывают мелкой строкой «также заезжает
   у {метро}» — прозрачность вместо запрета. Модерация `moving_in` строже:
   фото из квартиры, адекватная цена доли.
   **ПУЛА У «К СЕБЕ» НЕТ**: все претенденты хотят одну комнату одного человека,
   мэтчи между ними бессмысленны (для этого есть зонные пулы). Отклик =
   ДОРОГОЙ лайк автору напрямую с карточки (кнопка «Хочу эту комнату», из
   лимита 5 слотов/24ч, контекст = point_id). Автор видит отклики
   в «Тебя лайкнули» с пометкой «на твою комнату», взаимный лайк → мэтч.
   На карточке — счётчик «N откликов» (соревновательный сигнал), не
   «в пуле N». Спецэкрана «разбора откликов» у автора нет — только общий
   «Тебя лайкнули», как у всех.

**Дешёвый лайк** («Интересно — войти в пул») существует ТОЛЬКО для квартир
с рынка (`flat`): безлимитный, один тап, вход в пул точки. Для зонных пулов
и «к себе» жеста входа нет. Создатель пользовательской квартиры входит в её
пул автоматически при создании («ты первый в пуле» — буквально), ещё до
аппрува; выйдя из пула своей точки на проверке, обратно не войти (вход —
только в активные).

### 2.3 Дорогой лайк и мэтч (общие для всего)

**Дорогой лайк** = «хочу жить вместе»: ставится человеку только с экрана его
полного профиля (или кнопкой «Хочу эту комнату» на карточке «к себе»).
5 слотов; потраченный слот возвращается через 24 часа (скользящее окно, не
календарный день); остаток виден («осталось 3 из 5»), при нуле — «следующий
лайк освободится через N ч M мин» (относительное время, не абсолютный час:
«в 15:00» без даты двусмысленно). Правило «МЫ УВИДЕЛИСЬ»: чужой полный профиль
виден и дорогой лайк возможен, только если активные поиски двоих пересекаются
зонами (вы в одном пуле), ЛИБО есть входящий лайк от него, ЛИБО вы в мэтче;
стороннему человеку профиль отвечает тем же 404, что и невидимому. Тратящий
лайк требует поиска, пересекающего ЗОНУ КОНТЕКСТА; попытка без него →
мини-форма с предзаполненной зоной («укажи, где ищешь — и лайк улетит»,
после сохранения лайк уходит сам). Требования «любого поиска» (skin in the
game) больше нет: от туристов защищают одобренная анкета и цена слота. Для
точек поиск не нужен вовсе — отношение несёт сам контекст: у квартиры с рынка
тратящий лайк требует членства лайкающего в пуле точки, у «к себе» — что
адресат и есть автор карточки; профиль участника пула открыт со-пульнику,
профиль автора «к себе» — всем, кто видит карточку (витрина). Требует
также одобренной анкеты: в draft и pending дорогие лайки недоступны (403) — до
одобрения (§5). Лайк хранит контекст (zone_id ИЛИ point_id).
**Ответный лайк на входящий НЕ тратит лимит и НЕ требует активного
поиска** (автор «к себе» без поисков должен мочь ответить на отклик).
Лайк без username-контакта не блокируется: в мэтче тогда deep-link
tg://user?id и подсказка «он напишет тебе первым».

**Мэтч** = взаимные дорогие лайки (независимо от контекстов). Контакты обоим +
саммари «почему совпали» (совпавшие поля анкеты + зона/точка контекста). Мэтч
необратим, приватен для пары. Гонка одновременных взаимных лайков не должна
создавать дубль мэтча (транзакция/уникальный индекс).

Правила жизни лайка: дорогой лайк НЕ сгорает никогда и ни от чего — ни
выход из пула, ни изменение точки, ни закрытие поиска его не трогают.
Терминальные состояния лайка: мэтч или вечное ожидание ответа. Мэтч
постфактум валиден (вышел из пула — взаимный ответ позже всё равно даёт
мэтч; контекст в саммари исторический: «пересеклись в пуле X»). Вместо
гашения — прозрачность: если у лайкнувшего сейчас нет активных поисков,
его карточка в «Тебя лайкнули» несёт серую пометку «сейчас не в поиске» —
адресат сам решает, отвечать ли. Потраченный слот досрочно не возвращается
ничем — только истечением своих 24 часов.

Входящие лайки: раздел «Тебя лайкнули» (бейдж на табе «Профиль»). Каждый — с
именем сразу, с тапабельной мини-карточкой контекста (точка или зона) и кнопкой
«Ответить» → мэтч. Тап по контексту ведёт в пул, только если у адресата есть
свой поиск этой зоны (чужой пул не отдаётся, §2.3), иначе — сразу в профиль
лайкнувшего (он открыт по отношению «он меня лайкнул»). Чужие дорогие лайки
не видны никому, кроме адресата: ни счётчиков «его лайкнули N», ни публичных
нулей.

## 3. Жизненный цикл поиска

- Создание — входы в одно состояние: кнопка «Войти в пул {зоны} — сохранить
  поиск» внутри промо-блока людей в выдаче (основной), кнопка «Создать поиск»
  в «Моих поисках» и финале онбординга (тот же компонент параметров).
  Просмотр выдачи по параметрам НЕ создаёт поиск —
  подписка только явным сохранением. Изменение параметров — свободное
  (пул виртуален, никого не дёргает); лайки не затрагиваются (§2.3).
  ЗОНА ИММУТАБЕЛЬНА: зона — идентичность подписки (на ней держатся свежесть
  в пуле, бейдж «M новых» и пуши), смена зоны = новый поиск; форма нового
  может предзаполняться параметрами старого.
- TTL: «ещё ищешь?» раз в ~7 дней без активности; без ответа → пауза (человек
  скрывается из пулов, пуши по его поиску останавливаются). После мэтча —
  тот же вопрос с дедлайном 3–4 дня, молчание → пауза.
- Закрытие — с причиной: «нашёл здесь» (ГЛАВНАЯ МЕТРИКА) / «нашёл в другом
  месте» / «передумал». Закрытый поиск реактивируется кнопкой из «Моих поисков».
- Пуш-подписка: активный поиск = подписка на «появился новый совпавший в твоей
  зоне» (см. §7).

## 4. Анкета пользователя (онбординг)

Регистрации нет — вход по Telegram (initData). Онбординг = 12 шагов, ~2 мин.
Анкета выверена по ресерчу предикторов конфликтов сожителей (чистота, сон,
шум, гости/партнёр, деньги — сильные; хобби, психотипы, температура — не
предсказывают и в анкету не входят):

Дословные формулировки (микрокопию не «улучшать» при сборке):

0. Базовое: имя из TG; возраст (число); пол; «С кем готов жить?» →
   «С любым полом» / «Только свой пол». Подпись: «Это взаимно: если ты
   „только свой пол", другой пол тебя не увидит нигде».
1. «Чем занимаешься?» → «Учусь» / «Офис» / «Гибрид» / «Удалёнка» /
   «Сменный график». Подпись: «График занятости — это про то, когда
   квартира пустая».
2. «Когда ты активен?» → «Сова — поздно ложусь» / «Жаворонок — рано
   встаю» / «Плавает». Подпись: «Разный график — конфликт номер один
   у соседей». (Про время, не про звук — звук в шаге 5.)
3. «Куришь? (вейп и айкос тоже считаются)» → «Не курю» / «На балконе
   или улице» / «Дома».
4. Животные, два подвопроса на одном экране: «Свои животные?» → «Нет» /
   «Кот» / «Собака» / «Другое»; «Как к чужим?» → «Ок» / «Аллергия» /
   «Против».
5. «Какой звук дома норм?» → «Нужна тишина» / «Нормально» / «Сам шумный».
   Подпись: «Наушники или колонки — вот про это». (Про звук, не время.)
6. «Как часто у тебя гости?» → «Редко» / «Иногда» / «Часто» / «Партнёр
   регулярно ночует». (Партнёр — отдельный вариант: «наполовину живущий»
   партнёр — топ-конфликт сожителей.)
7. «Как у тебя с уборкой?» → «По расписанию» / «Убираю, когда грязно» /
   «Творческий беспорядок».
8. «Алкоголь дома?» → «Не пью» / «С соседом за сериалом — да» /
   «Тусовки — норм».
9. «Как тебе с общими тратами?» → «Делю поровну и плачу сразу» / «Веду
   учёт (Splitwise и т.п.)» / «Разберёмся по ходу». Подпись: «Деньги —
   вторая причина конфликтов соседей после уборки». Дохода не спрашиваем.
10. «О себе» — свободное поле до 200 знаков со счётчиком. ЕДИНСТВЕННЫЙ
    свободный текст во всём продукте. Подпись: «Диета, религия,
    температура в комнате — если важно, напиши здесь. Пройдёт проверку
    вместе с фото».
11. «Фото с лицом» → загрузка файла. Обязательное; валидация — глазами
    модератора (никакого face-detection на MVP). Аватар из Telegram НЕ
    подставляем: он может быть скрыт настройками приватности, поэтому путь
    «оставить как есть» работал бы не у всех и требовал бы ветки «а если
    аватара нет».

В анкете НЕТ бюджета/района/дат — это параметры поиска, не личности. Нет
предпочтений о соседе, кроме пола. Каждый вопрос — с подписью, зачем спрашиваем.
Финал онбординга — экран-развилка: галочка «Анкета готова» + плашка проверки
одной строкой («Уйдёт на быструю проверку — виден станешь после» + мелко
«пока можешь смотреть и сохранять поиски, лайки сохранятся»); затем ДВЕ
карточки-пути в цветах типов, обе тапабельные: розовая главная «Ищу, куда
съехать» («Настрой поиск — 20 секунд, покажем людей и квартиры» → форма
«Найти») и зелёная «Зову соседа к себе» («Уже живёшь в квартире или
заезжаешь — найди, кто въедет» → форма «к себе»); под ними тихая ссылка
«просто посмотреть ленту».

Пол — единственное серверное обоюдное правило видимости: при несовпадении
gender_pref люди друг для друга НЕ СУЩЕСТВУЮТ нигде (пулы, счётчики, пуши,
лайки, «тебя лайкнули»). Реализуется в ЕДИНОЙ функции/запросе видимости
visible_people(viewer_id, ...), через которую ходят ВСЕ потребители (зонный пул,
квартирный пул, счётчики, пуши, валидация лайка). gender_pref NOT NULL DEFAULT
'any'. Счётчики из-за этого персональные. Блокировки (blocks) — та же проверка.

## 5. Модерация и доверие

- Статусы анкеты: **draft** (аккаунт создан первым запуском, анкета не
  дозаполнена — регистрации нет, §4) → **pending** (отправлена, ждёт
  модератора) → **active** (одобрена, видна везде). Отдельно **banned** —
  исход разбора жалобы. В draft и pending права одинаковые: МОЖНО листать
  ленту, создавать поиски, входить в квартирные пулы; НЕЛЬЗЯ быть видимым
  другим и ставить дорогие лайки. После аппрува человек «проявляется» везде
  разом. Разделение draft/pending обязательно: в очередь модерации попадают
  только отправленные, черновик продолжают с брошенного шага, и микрокопия у
  них разная («заполни анкету» против «анкета на проверке»). Определять
  готовность по «все поля анкеты не NULL» нельзя — предикат придётся повторять
  в каждом запросе и переписывать при добавлении вопроса.
- Модерация ручная, в отдельном ТГ-чате основателя (MODERATION_CHAT_ID;
  пусто — очереди копятся, команда /queue в чате досылает накопленное), две
  очереди: анкеты (фото + «о себе»: ок / фото не ок / текст не ок) и
  пользовательские точки (ок / отклонить; для «к себе» дополнительно: фото
  комнаты не стоковое, цена доли адекватна рынку). Вердикты идемпотентны:
  тап по устаревшей кнопке — «уже обработано», одобрить можно только то, что
  сейчас в очереди (стухшая кнопка «ок» не воскрешает отклонённое). Любой
  вердикт по забаненному — no-op: «забанить» — исход разбора жалоб
  (скам/угрозы), не инструмент модерации контента, и разбаниваться тапом по
  старой кнопке нельзя. Поиски НЕ модерируются (структурные, текста нет).
- Реджект фото ≠ бан, но и не «виден с оговоркой»: фото ОБЯЗАТЕЛЬНО (§4,
  шаг 11), поэтому анкета с отклонённым фото возвращается в **draft** и
  пропадает из выдачи до перезагрузки фото. Причина остаётся в photo_status =
  rejected, уходит пуш «загрузи другое». Статуса «без фото» НЕТ — он
  противоречил бы обязательности фото. Следствие: пуш «загрузи другое» —
  единственная дорога назад, терять его нельзя.
- Редактирование одобренной анкеты: на перепроверку уходят ТОЛЬКО фото и
  «о себе» — ровно то, что модератор смотрит. Привычки, возраст, занятость
  меняются молча: правка «сова → жаворонок» не должна выкидывать человека из
  пулов. Статус пользователя при этом НЕ меняется, он остаётся **active**;
  сбрасывается только photo_status / about_status в pending. Пока фото не
  одобрено — вместо него ЗАГЛУШКА, пока не одобрено «о себе» — блок не
  показывается вовсе. Теневых копий полей нет: перезалитое фото затирает
  одобренное, и если новое отклонили, заглушка стоит до следующей загрузки.
  Отсюда ДВЕ ветки реджекта фото: у не прошедшего проверку ни разу — возврат
  в draft (выше), у активного — статус не трогаем.
- Точка создателю видна сразу (статус «на проверке»), в общую ленту — после
  аппрува. Автовалидация до модератора: ссылка только avito.ru/cian.ru, цена
  20–300к, метро из справочника.
- Верификация почтой — ОПЦИОНАЛЬНАЯ (не гейт): домен вуза → бейдж (вайтлист
  доменов в конфиге, старт — 2–3 вуза), позже корп-домены той же механикой.
  Лейбл по занятости: «учебная» студенту, «рабочая» работающему. Всегда бесплатна.
- Блок: кнопка в профиле → обоюдная невидимость немедленно. Жалоба: кнопка →
  саппорт-бот с предзаполненным контекстом (кто, на кого, из какого
  пула/мэтча) → ручной разбор.
- Бан пира или блок пары НЕ стирает мэтч из списков (§2.3: мэтч необратим), но
  контакты в деталях мэтча скрываются — «Контакт недоступен».
- Существенное изменение точки (цена, зона, комнаты) → пуш пулу с дельтой
  («90к → 110к»); лайки не затрагиваются. Косметика — молча.

## 6. Экраны

Табы: **Лента / Мои поиски / Профиль** (+бейдж входящих лайков на Профиле).

- **Лента — search-first, три шага.** (1) Вход: без активного поиска — экран
  с заголовком «С кем и где будешь жить?», большой кнопкой «Найти» и тизером
  свежих карточек Москвы ниже; с активным поиском — сразу выдача его
  параметров («Найти» остаётся для нового поиска). (2) Форма параметров: зона
  (район/станция/ветка, обязательна) + бюджет-вилка + опционально комнатность,
  заезд; кнопка «Показать» + подпись «Это ещё не подписка — просто посмотрим,
  что есть». Поиск ≠ подписка: смотреть выдачу можно без сохранения.
  ИСКЛЮЧЕНИЕ: если на зону формы у смотрящего уже есть активный поиск,
  «Показать» заодно обновляет его (подпись меняется на «Обновит твой
  сохранённый поиск в этой зоне») — иначе счётчик промо жил бы по форме,
  а пул по подписке, и они врали бы друг другу.
  (3) Выдача: чипы текущих фильтров (БЕЗ кнопок в них — просто параметры
  просмотра; «Изменить» в шапке открывает форму). Первым в списке — промо-блок
  людей (розовый): заголовок «N человек ищут в {зоне}» (формулировка по типу
  зоны: «в Хамовниках» / «на оранжевой ветке» / «у метро Сокол») + подстрока
  «с K полное совпадение по твоим параметрам» + стек аватаров + внутри блока
  кнопка **«Войти в пул {зоны} — сохранить поиск»** с подписью «Пул собирается
  по месту. Твои параметры сохранятся как поиск · слот X из 3». Состояния
  блока: обычное / после сохранения («Ты в пуле {зоны} · поиск сохранён»,
  зелёное) / пустая зона («никто пока не ищет — войди в пул первым, пришлём
  пуш») / слоты заняты («поиски заняты 3 из 3» → тап в «Мои поиски» с
  предложением закрыть один). Сохранение поиска происходит ТОЛЬКО здесь —
  в чипах фильтров кнопки сохранения нет.
  Ниже единым списком карточки точек: бирюзовая «Квартира с рынка»
  (источник+дата, фото, цена общая + «с человека», «в пуле N»), зелёная
  «Сосед к себе — уже живёт там» (лицо, «была вчера», комната, цена доли,
  «N откликов»). Кнопки создания точек в ленте НЕТ — создание живёт в
  «Моих поисках».
- **Зонный пул** (из баннера или карточки-подписки): плашка подтверждения
  подписки сверху; три секции — «Совпали по всем параметрам · N» / «Пересекаются
  частично · N» / «Не совпали · N» (приглушены, свёрнуты после первого, «ещё K»).
  Мини-карточка человека: аватар, имя+бейджи, привычки-строка, зона его поиска
  («ищет на красной ветке»; при полном территориальном совпадении — равные или
  вложенные зоны — строка зелёная с пометкой «твоя зона», и такие карточки
  стоят выше внутри своей секции), «N совпадений
  анкеты», чипы его параметров с вердиктами (✓ зелёный / «краем» жёлтый / серый).
  NULL-параметр = «неважно»: совпадает со всем, у других показывается серым
  «не указана». Тап → профиль. Подсказка плотности — один компонент, три
  состояния: пусто («подпишись первым — пришлём пуш»), норм (ничего),
  перебор >50 совпавших («уточни бюджет или сузь зону — список станет
  точнее»); хвост несовпавших отсекается топ-N с «уточни параметры».
  Внизу пула — тихая ссылка «Квартиры под этот поиск · M» → выдача
  (мостик к жилью для пришедших сразу в пул).
- **Карточка квартиры**: фото, цены, параметры, источник/дата/ссылка на оригинал,
  «в пуле N — увидишь после входа», кнопка «Интересно — войти в пул» + подпись
  «Вход бесплатный и безлимитный». Пул квартиры — список лайкнувших с
  совпадениями анкеты и вердикт-чипами (если у смотрящего есть поиск), кнопка
  «Выйти из пула» (красная, простое подтверждение; лайки не сгорают и в
  шторке не упоминаются).
- **Карточка «к себе»**: лицо + зелёный бейдж «живёт здесь», мини-карточка
  комнаты, счётчик «N откликов», кнопка «Хочу эту комнату» = сразу дорогой
  лайк автору (тратит лимит, подпись с остатком «3 из 5»). Экрана пула нет.
- **Профиль человека**: фото, имя, занятость, бейджи, «был сегодня»; совпадения
  анкеты (зелёное «вы оба», нейтральное с контекстом, красного НЕТ); «о себе»;
  контекст «пересеклись: {зона/точка}». Кнопка «Хочу жить вместе» (единственная
  залитая, в TMA — MainButton) + остаток «3 из 5». Без поиска, пересекающего
  зону контекста (редкая гонка «поиск умер, пока смотрел профиль»), — кнопка
  ведёт в мини-форму с предзаполненной зоной, после сохранения лайк уходит сам.
- **Мэтч**: «Это мэтч» + саммари тремя блоками: (1) ГДЕ — мини-карточка
  контекста: «пересеклись в пуле Хамовников» / «на комнату Кати · м. Сокол»;
  (2) ПО ПАРАМЕТРАМ — пересечение поисков конкретикой: «бюджет: у обоих
  40–45к», «заезд: сентябрь у обоих»; (3) ПО АНКЕТЕ — зелёные чипы совпавших
  привычек: совпавшие ответы одиночными лейблами («сова», «не курю»), «вы оба»
  несёт заголовок блока. Саммари — готовые темы для первого сообщения.
  Кнопка «Написать @username».
- **Тебя лайкнули**: входящие с мини-карточкой контекста (тап → пул),
  «Профиль» / «Ответить»; сверху «Ответный лайк не тратит лимит».
- **Мои поиски** — три блока по роли:
  (1) «Мои поиски» — до 3 поисков карточками: параметры, счётчики («N ищут ·
  с K полное совпадение», бейдж «M новых»), кнопка «Смотреть пул · N» —
  ведёт СРАЗУ в зонный пул (люди; из «Моих поисков» приходят за людьми),
  тапабельная строка «M квартир под эти параметры» — ведёт в выдачу;
  редактировать, закрыть с причиной, реактивация из архива;
  «Создать ещё» с остатком слотов. Пуши «новый ищущий» диплинкают сюда,
  на табе — бейдж новизны.
  (2) «Присмотренные квартиры · N из 5» — СОЗДАННЫЕ (только они считаются в
  лимит 5): статус («на проверке» / «скрыта» у paused), позвать в чат,
  закрыть (без причин — причина закрытия есть только у поиска, §3; закрытие
  освобождает слот, повторная подача той же ссылки разрешена). Ниже, в том же
  блоке — квартиры, в чьи пулы вошёл (без лимита): «в пуле N», тап → пул.
  Кнопка «Присмотрел квартиру? Найди, с кем её снять»; пустое состояние:
  «Присмотрел вариант на Авито? Собери на него людей».
  (3) «Зову к себе · N из 2» (зелёный акцент типа) — точки «к себе» со
  стадией-бейджем и «N откликов», либо кнопка «Ищу соседа к себе»; пустое
  состояние: «Живёшь в квартире или заезжаешь — найди соседа». Отдельного
  экрана/шторки выбора типа создания НЕТ — выбор кнопками блоков.
- **Профиль свой**: фото, имя, строка статуса — «анкета на проверке» (pending)
  / «заполни анкету» с возвратом на брошенный шаг (draft, в том числе после
  реджекта фото); редактировать; «Тебя лайкнули · N»; верификация почты;
  «Мои мэтчи» — список БЕЗ контактов, контакты только в деталях мэтча.
- **Пустая лента зоны**: «пусто — растём из района в район» → карточка-подписка
  «подпишись первым» → топ живых зон/точек рядом по числу людей.
- Создание квартиры — подача «личная задача, не каталог»: заголовок формы
  «Найди, с кем снять эту квартиру», подпись «Соберём людей, готовых
  снять её с тобой». Поля: ссылка (валидация домена; если URL уже есть — «эта
  квартира уже есть, в пуле N — войти?») + метро, цена, комнаты/изолированность,
  фото-скрины (до 10, первое — обложка); опционально: санузлы (число/раздельный), коммуналка
  (включена/счётчики), лимиты собственника чипами («не сдают парам»,
  «без животных» — показывать на карточке заранее: рушат мэтч до контакта); калькулятор «с человека»; финал «ты первый в пуле» + строка
  форы «Ты видишь всех входящих первым — пуш о каждом» + «Позвать в
  пул — поделиться в чат» (вирусная петля).

## 7. Уведомления (через бота)

MVP-типы: «новый ищущий в {зоне}, пересекается с твоим поиском» (по подписке;
при полном совпадении параметров — усиленная формулировка «совпали все
параметры: бюджет, заезд»; агрегируется,
не чаще 1 пуша/зону/день), «в пуле {точки} появился человек» (первому-ждущему
в пуле квартиры с рынка; уникальность по (актор, пул)), «тебя лайкнул {имя}»
(с контекстом; отклик на «к себе» приходит этим же типом с пометкой «на твою
комнату»), «мэтч с {имя}». Сервисные: «квартира, похоже, сдана — но вы уже нашли
друг друга, вот похожие» (пулу при скрытии точки), «точка
изменилась» (информационный), «анкета одобрена / фото отклонено», TTL «ещё
ищешь?», пост-мэтч опрос через 5–7 дней («съезжаемся / общаемся / не сложилось»,
без наград). Общий rate-limit: ≤2–3 пуша в день на юзера. Лог notifications
с уникальным индексом — дубли невозможны на уровне БД.

## 8. Контент и лимиты

- Источники квартир: парсер ТГ-каналов аренды (MTProto, отдельный сервис,
  допустим Python+Telethon) → LLM-структуризация поста в JSON, вкл. санузлы, коммуналку и лимиты
  собственника, если есть в посте → source=
  'tg_channel', сразу active, без created_by; пользовательские ссылки
  (source='user_link', premoderation, created_by, лимит 5); ручная досыпка
  (source='manual', как tg_channel). Авито/Циан НЕ парсим. source='realtor' —
  заготовка, пост-MVP. created_by — provenance и лимиты, НЕ владение; в
  продуктовых выборках не участвует; nullable.
- Свежесть рыночных квартир — краудсорс как основной механизм: после
  перехода по ссылке на оригинал (переход через приложение) — шторка
  «Объявление ещё живое?» → «Да» / «Уже сдана». Порог скрытия:
  max(2, 30% пула) голосов «сдана» → точка paused «похоже, сдана», пуш
  пулу. Один голос — только пометка в строке свежести. Для user_link
  создатель видит причину в «Присмотренных» + кнопка «Проверил — она
  живая» (восстанавливает, сбрасывает голоса; повторное скрытие —
  финальное до явного подтверждения создателя). У tg_channel/manual
  создателя нет — сразу архив. Строка свежести на карточке: «подтверждена
  вчера» (есть свежие «да») / «добавлена N дней назад, не проверялась»;
  точность до дня, «20 минут назад» не обещаем. Страховки: TTL ~14 дней
  без подтверждений → архив; пост удалён из ТГ-канала → точка гаснет;
  еженедельный пинг создателю user_link. Поле points.last_seen_alive +
  таблица голосов.
- Плотность важнее полноты: досыпку и парсинг концентрировать в районах посева,
  хотя продукт открыт на всю Москву. user_link — НЕ источник объёма, а квартиры
  с горячим искателем внутри (добавляют под себя, не «в каталог»); объём дают
  парсер и досыпка.
- Лимиты: поисков ≤3 (зоны могут пересекаться, §2.1), пользовательских квартир ≤5,
  дорогих лайков — 5 слотов, окно 24 часа, «о себе» ≤200 знаков.
- Ранжирование ленты точек: размер пула с time-decay (score ~ pool/(age+c)^k).
  Отдельного правила «анкеты без фото ниже» нет: у всех видимых фото одобрено
  (§5), анкеты без него в выдачу не попадают вовсе.
- Справочник зон: станции, ветки, районы Москвы; зона → множество станций;
  пересечение зон = пересечение множеств. Конечный, версионируемый в репе.

## 9. Вырезано из MVP / отменено — НЕ РЕАЛИЗОВЫВАТЬ без явного запроса

ОТМЕНЕНО (не «потом», а никогда в этой модели): любое сгорание/гашение
дорогих лайков (при выходе из пула, изменении точки, закрытии поиска) и
окно возврата лайков; заявка (intent) как
пользовательская точка сбора с автором; пул-центричная карточка заявки;
дешёвый лайк на заявку; переезд заявки; копия заявки; дедупликация заявок.

ОТЛОЖЕНО: скор совместимости (только счётчик совпавших полей), карта, дайджест
роста квартирного пула, «как меня видят», риелторские фиды, монетизация (вся),
KYC/платная верификация, face-detection, экран возвращенца, комментарии при
входе в пул, статус «сейчас ищу», показ чужих дорогих лайков кому-либо кроме
адресата, награды за пост-мэтч опрос; персональные жёсткие фильтры по
дил-брейкерам (курение, животные) — триггер: плотные пулы (на старте это
сигналы сортировки с вердикт-чипами, жёсткая отсечка убьёт тонкие пулы);
вопрос про стиль решения бытовых споров — прогрессивное профилирование
после первого мэтча, не в онбординг; автоматический чекер доступности
URL объявлений (раз в сутки по активным точкам) — триггер: 100+ живых
квартир или краудсорс перестал успевать.

Тюнинг больших пулов — триггер: зоны со стабильными 50+ совпавшими (сейчас
НЕ делать): ротация равных по скору, буст свежих, приоритет менее залайканных
(анти-матфей), сортировка входящих лайков по совпадению, авто-протухание
неотвеченных входящих.

## 10. Стек и архитектура

- **Бэк**: Go, структурированный монолит: доменные пакеты (users, searches,
  points, pools, likes, matches, notifications, moderation), тонкие слои
  handler → service → storage; интерфейсы на границах слоёв — всегда, объявлять
  на стороне потребителя. SQL руками через pgx (без ORM). PostgreSQL. Валидация
  TMA initData (HMAC). Пуши: Bot API sendMessage. Правило видимости — одна
  точка (visible_people), какой бы пакет её ни вызывал.
- **Парсер**: отдельный сервис (Python+Telethon допустим), общается с бэком
  только через БД. LLM-вызов для структуризации постов.
- **Фронт**: React + TypeScript + Vite. @telegram-apps/sdk-react (initData,
  тема, MainButton/BackButton), @telegram-apps/telegram-ui. Цвета — переменные
  темы Telegram; кастом — только шапки типов карточек и акцентная кнопка.
- **Инфра**: один VPS, docker compose (api, parser, postgres), Caddy (HTTPS
  обязателен для TMA), фронт — статика. Без k8s/redis/очередей.
- **Модерация**: тот же бот, отдельный чат основателя, inline-кнопки.

## 11. Схема данных (ориентир, уточняется в коде)

users(id, tg_id, name, age, gender, gender_pref NOT NULL DEFAULT 'any',
  occupation, schedule, smoking, pets_own, pets_ok, noise, guests, cleaning,
  alcohol, about, photo_key, photo_status[pending/ok/rejected],
  about_status[pending/ok/rejected], onboarding_step NOT NULL DEFAULT 0,
  status[draft/pending/active/banned] NOT NULL DEFAULT 'draft',
  last_seen, created_at)
  — photo_key, а не photo_url: в базе КЛЮЧ объекта, URL собирает хранилище.
    Иначе адреса локального стенда запекаются в строки и ломаются при
    переезде на боевое S3
  — onboarding_step — закладка «куда возвращать бросившего»; сервер её хранит
    и отдаёт, но НИЧЕГО на ней не строит: порядком экранов владеет фронт
  — статус 'unknown' в БД не хранится: это значение уровня кода, которым
    маппинг описывает нераспознанную строку (схема ушла вперёд бинаря),
    и оно НЕ видимо, как и всё, кроме 'active'
zones(id, kind[district/station/line], name, station_ids[])   — справочник
searches(id, user_id, zone_id, price_min NULL, price_max, rooms_min NULL,
  rooms_max NULL, move_in NULL, term NULL, has_stuff[],
  status[active/paused/closed], close_reason NULL, created_at, updated_at)
  — ≤3 active на юзера, единственная валидация; зоны пересекаться могут (§2.1)
points(id, type[flat/intent_home], stage NULL [live/moving_in — только для
  intent_home], status[pending/active/paused/closed],
  source[tg_channel/user_link/manual/realtor], created_by NULL, zone_id,
  price_total NULL, price_share NULL, rooms NULL, isolated NULL,
  bathrooms NULL [combined/separate/two], utilities NULL [included/meters],
  restrictions[] [no_pets/no_couples/no_smoking — коды, лейблы у UI],
  photo_keys[] (до 10, первое — обложка карточки и кадр модерации),
  url_norm NULL, move_in NULL, deposit NULL,
  close_reason NULL, created_at, edited_at)
  — CHECK: created_by IS NULL ⇔ source IN ('tg_channel','manual');
    intent_home ⇔ stage NOT NULL, intent_home → created_by NOT NULL;
    closed ⇔ close_reason; moving_in → move_in
  — url_norm: частичный УНИКАЛЬНЫЙ индекс WHERE status <> 'closed' —
    переподача закрытой/отклонённой ссылки разрешена; url_norm — единственный
    носитель ссылки (исходный URL не хранится, наружу уходит нормализованный)
  — лимиты в транзакции создания (лок строки создателя): user_link+flat ≤5
    живых (pending+active), intent_home: live=1, всего ≤2; closed не считается
  — создатель flat автоматически в likes_points своей точки (§2.2)
likes_points(user_id, point_id, created_at)             — вход в пул, ТОЛЬКО type=flat
point_changes — НЕ создана: редактирования точек в MVP нет (§6 его не даёт);
  появится вместе с дельта-пушами, когда редактирование появится
likes_users(from_id, to_id, zone_id NULL, point_id NULL, spent boolean NOT NULL,
  created_at)
  — дорогой лайк с контекстом; UNIQUE(from_id, to_id)
  — spent решается при вставке и не пересчитывается: ответные лайки не тратят
    слот, а окно бюджета (24ч) считается по spent-лайкам этого from_id
  — частичный индекс по point_id (WHERE NOT NULL) — под счётчик откликов
matches(id, a_id, b_id, context_zone_id NULL, context_point_id NULL, created_at)
  — из взаимных лайков; контекст — копия контекста ПЕРВОГО лайка пары
    (поиски к моменту мэтча могут быть уже закрыты); пара канонична
    (a_id < b_id) + UNIQUE(a_id, b_id) — гонка не даёт дубля
blocks(blocker_id, blocked_id)
verifications(user_id, type[edu_email/corp_email], org_domain, verified_at)
orgs(domain, name, kind[university/company])
notifications(id, user_id, type, payload, sent_at, UNIQUE по смыслу типа)
