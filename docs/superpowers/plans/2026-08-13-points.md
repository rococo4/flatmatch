# Точки (§12 шаг 5) — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Задачи трекаются чекбоксами.

**Goal:** Точки двух типов (квартира с рынка, «сосед к себе»), квартирные пулы с дешёвым входом, дорогие лайки с point-контекстом, лента с точками, блоки 2–3 «Моих поисков», модерационный чат на обе очереди §5.

**Architecture:** Спека — `docs/superpowers/specs/2026-08-13-points-design.md` (истина при конфликте с планом; CLAUDE.md на диске — истина продукта). Монолит: `pointsrepo` → `points`/`moderation` сервисы → `pointsapi` + расширения likes/people/matches/pools; tgbot получает callback_query. Фронт оживляет готовые DEMO-экраны.

**Tech Stack:** Go 1.26, pgx v5, goose, chi; React+TS+Vite.

## Global Constraints

- Комментарии в Go — только неочевидные «почему», скупые (пользователь вычищает описательные).
- Русская микрокопия — дословно из спеки, идентификаторы/логи — английские.
- Интерфейсы на стороне потребителя; visible_people — единственная точка видимости (§4).
- Правило «мы увиделись» (§2.3, коммит 8381586) — для точек: co-membership пула flat / карточка-витрина intent_home; поиск для точечных лайков НЕ требуется.
- Смэтченные скрыты из discovery-выборок (участники пула точки — тоже discovery).
- Дорогие лайки не сгорают НИКОГДА (§9): выход из пула их не трогает.
- created_by — provenance, в продуктовых DTO не светится (§2.2: точка обезличена; исключение — автор intent_home, он витрина).
- Лимиты: user_link ≤5 живых (pending+active) на создателя; intent_home live=1, moving_in ≤2, всего ≤2 живых; проверка — лок строки users + счёт ОТДЕЛЬНЫМ стейтментом (READ COMMITTED, урок шага 3).
- Каждая задача: тесты → реализация → `go build ./... && go vet ./... && TEST_DATABASE_URL='postgres://flatmatch:flatmatch@localhost:5432/flatmatch?sslmode=disable' go test ./...` (фронт: `npx tsc --noEmit && npm run build`) → коммит в main (`Co-Authored-By: Claude Fable 5 <noreply@anthropic.com>`), без push.
- Аккаунт tg_id=188993596 в БД не трогать.
