# parser — заглушка

Отдельный сервис, который наполняет `points` квартирами с рынка (§8). Пока
не реализован: это шаг 7 в §12, до него доходим после пушей.

## Что он будет делать

1. Читать заранее заданные ТГ-каналы аренды через MTProto (Telethon).
2. Отдавать текст поста в LLM и получать JSON: метро, цена, комнатность,
   изолированность, санузлы, коммуналка, ограничения собственника.
3. Писать в `points` с `source='tg_channel'`, сразу `status='active'`,
   `created_by = NULL`.

Авито и Циан не парсим — оттуда приходят только пользовательские ссылки
(`source='user_link'`), которые люди добавляют под себя.

## Границы

С бэкендом общается **только через базу** (§10). Общего кода, общих очередей
и HTTP-вызовов между `api` и `parser` нет и не планируется — это единственный
интерфейс между ними.

## Запуск

Сервис выключен по умолчанию: в `docker-compose.yml` он под профилем.

```sh
docker compose --profile parser up -d
```

Понадобятся `TG_API_ID` / `TG_API_HASH` с https://my.telegram.org и ключ
LLM-провайдера — переменные добавим вместе с реализацией.
