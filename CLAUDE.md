# FlatMatch — спека продукта и техконтекст (v2, модель «поиски-подписки»)

Этот файл — единственный источник правды по продукту. Все правила ниже — финальные.
Если реализация конфликтует со спекой — спека права. Ничего из §9 «Вырезано»
не реализовывать, даже если «дёшево добавить».

ВАЖНО: в ранних версиях продукта существовала сущность «заявка» (intent) —
пользовательская точка сбора «ищу со-съёмщика» с автором. Она ОТМЕНЕНА и заменена
моделью поисков-подписок (§2–3). Если где-то встретишь след заявок — это ошибка.

## 1. Что это

Telegram Mini App для поиска со-съёмщика квартиры. Рынок: Москва целиком, без
ограничения по районам. Аудитория — все, кто ищет со-съёмщика; продукт не
студенческий: студенты — приоритетный сегмент посева (август–сентябрь) и
получают бейдж вуза, но никаких гейтов по аудитории нет.

Позиционирование: **не агрегатор квартир, а поиск людей.** «Квартиру найдёшь где
угодно — мы найдём того, с кем её снимать». Метрика успеха — мэтч, дошедший до
совместного поиска/заселения (поиск, закрытый с причиной «нашёл»).

## 2. Ядро механики

Ядро — люди и их поиски-подписки; интерфейс над ними — карточный подбор
(вкладка «Соседи», внутреннее имя deck; слова «пул» в UI нет). Рыночные
квартиры ВЫКЛЮЧЕНЫ (этап 1, §8) — из точек жива только «к себе». Всё
сходится в одном месте: анкета → дорогой лайк → мэтч.

### 2.1 Поиски и зонные пулы (люди ↔ люди)

**Поиск (search)** — подписка пользователя на параметры: одна зона из справочника
(район / станция / ветка метро) + бюджет-вилка «с человека» (от опционально — до)
+ опционально: комнатность (набор из «1 / 2 / 3 / 4+»), месяцы заезда
(набор), срок (набор из полгода+/год+/бессрочно), чипы «что уже есть»
(мебель/техника). Пустой набор = «неважно». До 3 активных поисков на человека —
единственный лимит; зоны поисков МОГУТ пересекаться («Хамовники» + «красная
ветка» — два честных разных намерения с разными бюджетами, запрещать их
пересечение значило бы, что ветка блокирует все районы вдоль себя). В пуле
человек при этом один раз (см. §2.1, лучший вердикт). Точный дубль зоны сервер
тоже не запрещает: «Сохранить и смотреть» на зоне с уже существующим
активным поиском обновляет его, а не плодит дубль (§6).

Набор фильтров ЗАФИКСИРОВАН (по ресерчу практик flatshare-продуктов), не
расширять: зона (граница пула), бюджет-вилка «с человека», комнатность,
месяц заезда, срок. Пол — серверное правило видимости (§4), в UI фильтром
не является. Курение, животные и прочие привычки анкеты — НЕ фильтры, а
сигналы сортировки и вердикт-чипы (персональные жёсткие дил-брейкеры —
§9, отложено до плотных пулов). Фильтров по хобби, интересам, «типу
личности» не существует и не будет — не предсказывают совместимость,
схлопывают выдачу.
Поиск не публикуется как карточка — он включает человека в зонные пулы и питает
мэтчинг и пуши.

**Зонный пул** — вычисляемое множество: все люди с активным поиском, чья зона
пересекается с зоной пула. НЕ хранится как сущность, нет владельца, нет
«создания» и «входа»: создал поиск → автоматически виден во всех пулах,
чьи зоны пересекают твою; закрыл поиск → исчез. Пересечение зон — по справочнику
(поиск «Сокол» виден в пуле «оранжевая ветка», т.к. станция Сокол на ней).

Пулы не рисуются списками: смотрящий листает ОДИН подбор по всем своим
активным поискам — карточки людей и комнат «к себе» вперемешку, человек в
подборе один раз (дедуп). Сравнение и бейджи карточки — по ЛУЧШЕЙ паре
«мой поиск × его поиск» из пересёкшихся зонами: выше секция → больше
зелёных чипов → мой более свежий поиск; то же правило — в саммари мэтча.
Порядок подбора — секция лучшей пары (полное → частичное → нет), внутри —
свежие вперёд. Совпадение = ПЕРЕСЕЧЕНИЕ, не
равенство фильтров: у цены — пересечение вилок («35–45» и «40–55» совпали),
у комнат, срока и заезда — общий элемент наборов («2 или 3» и «3 или 4»
совпали). NULL-параметр и пустой набор = «неважно», совпадает со всем. Формула секций: жёсткие параметры — цена и заезд, мягкие —
комнатность и срок; «полностью» = пересеклись все указанные обоими параметры,
«частично» = пересеклись цена ИЛИ заезд, но не всё, «не совпали» = ни цена,
ни заезд. У каждого человека — чипы его параметров с вердиктом против твоих:
зелёный ✓ (пересеклись), жёлтый «краем» (границы вилок цены касаются —
только у цены, у наборов «краем» нет), серый (не пересеклись / «не
указана»). Жёсткая граница пула — только зона; всё
остальное — сортировка и пометки, НЕ отсечка. Фильтры подбора (тип
карточки, возраст, животные, курение, режим, занятость — мультивыбор,
пусто = неважно) — необязательное сужение по анкете: не правило видимости,
живут на клиенте (localStorage) и уходят параметрами deck-запроса. Подбор виден ТОЛЬКО со своим
активным поиском (правило «мы увиделись», §2.3) — анонимного просмотра
людей нет, и режима «посмотреть без подписки» тоже: кнопка формы —
«Сохранить и смотреть», просмотр = подписка. Тизер для неподписанных —
«ГДЕ УЖЕ ИЩУТ» (топ зон со счётчиками, без имён). Подбор и его счётчики не
показывают смэтченных, уже лайкнутых мной и пропущенных; фильтр стоит в
выборках discovery, НЕ в visible_people: пара остаётся видимой друг другу
в мэтче и его деталях. На карточке «к себе» у смэтченного — «✓ У вас мэтч»
вместо кнопки.

**Пропуск** — свайп влево (стрелка): цель уходит из подбора на 7 дней
(passes), потом возвращается сама. Пропуск ЧЕЛОВЕКА прячет и его карточку
комнаты (иначе отклонённый автор комнаты всплывал бы сразу); пропуск
КОМНАТЫ человека не прячет («не эта комната» ≠ «не этот человек»); «Показать пропущенных
· N» в конце подбора стирает все пропуски смотрящего разом. Отклонение
входящего лайка — тот же пропуск того же человека: входящий скрыт 7 дней,
сам лайк НЕ сгорает (§2.3).

### 2.2 «К себе» (комната → отклики); рыночные квартиры выключены

Рыночные квартиры (`flat`: парсер ТГ-каналов, пользовательские ссылки с
Авито/Циан) выключены этапом 1: парсер остановлен, точки закрыты, их UI и
дешёвый лайк удалены; код и таблицы заморожены до этапа 2 (§9). Причина:
гонка за полноту объявлений — чужая (Авито/Циан), ценность продукта — люди.

**«Сосед к себе»** (`intent_home`) живёт: у человека есть конкретное жильё
и нужен со-съёмщик под него. ДВЕ СТАДИИ (поле stage): `live` — уже живёт,
бейдж «Комната · сосед уже живёт там»; `moving_in` — договорился с
собственником и заезжает, бейдж «заезжает», дата заезда обязательна. Гейт
формы прежний: «уже живу здесь» / «договорился и заезжаю» / иначе — не наш
кейс (для сдачи — классифайды). Карточка в подборе — КОМНАТА первой: фото
комнаты (до 10, первое — обложка, пейджер), метро, ЦЕНА ДОЛИ въезжающего
(«Твоя доля»), изолированность, депозит, ОПИСАНИЕ (свободный текст ≤ 400,
проходит модерацию вместе с фото), ограничения квартиры чипами («нельзя с
животными» и т.п. — показывать ДО отклика); автор — строкой внизу (тап по
строке — его анкета, тап по карточке — экран комнаты). Отклик = сердце
«Хочу эту комнату» — дорогой лайк автору (из лимита 5/24ч, контекст =
point_id). Автор видит отклики во вкладке «Лайки» с бейджем «на твою
комнату», взаимный лайк → мэтч. На карточке — счётчик «N откликов». ПУЛА у
«к себе» нет: претенденты друг другу не нужны (для этого подбор людей).
Лимиты по стадиям: `live` — строго 1, `moving_in` — до 2, суммарно ≤2
активных; слот поисков НЕ занимает. Модерация `moving_in` строже: фото из
квартиры, адекватная цена доли. Точка смертна вместе с предложением (TTL и
пинг — §8).

### 2.3 Дорогой лайк и мэтч (общие для всего)

**Дорогой лайк** = «хочу жить вместе»: сердце/свайп вправо на карточке
подбора, кнопка на полной анкете, «взаимно» из «Лайков» или «Хочу эту
комнату» на комнате.
5 слотов; потраченный слот возвращается через 24 часа (скользящее окно, не
календарный день); остаток виден («осталось 3 из 5»), при нуле — «следующий
лайк освободится через N ч M мин» (относительное время, не абсолютный час:
«в 15:00» без даты двусмысленно). Правило «МЫ УВИДЕЛИСЬ»: чужой полный профиль
виден и дорогой лайк возможен, только если активные поиски двоих пересекаются
зонами (вы в одном пуле), ЛИБО есть входящий лайк от него, ЛИБО вы в мэтче;
стороннему человеку профиль отвечает тем же 404, что и невидимому. Тратящий
лайк требует поиска, пересекающего ЗОНУ КОНТЕКСТА; попытка без него →
мини-форма с предзаполненной зоной («укажи, где ищешь — и лайк улетит»,
после сохранения лайк уходит сам). Требования «любого поиска» (skin in the
game) больше нет: от туристов защищают одобренная анкета и цена слота. Для «к себе»
поиск не нужен вовсе — отношение несёт сама карточка: тратящий лайк
требует, что адресат и есть автор; анкета автора открыта всем, кто видит
карточку (витрина). Требует
также одобренной анкеты: в draft и pending дорогие лайки недоступны (403) — до
одобрения (§5). Лайк хранит контекст (zone_id ИЛИ point_id).
**Ответный лайк на входящий НЕ тратит лимит и НЕ требует активного
поиска** (автор «к себе» без поисков должен мочь ответить на отклик).
Лайк без username-контакта не блокируется: в мэтче тогда deep-link
tg://user?id и подсказка «он напишет тебе первым».

**Мэтч** = взаимные дорогие лайки (независимо от контекстов). Контакты обоим +
саммари «почему совпали» (совпавшие поля анкеты + зона/точка контекста). Мэтч
приватен для пары и живёт, пока одна из сторон не удалит его: «Удалить
мэтч» (любая сторона, без согласия второй) стирает мэтч и ОБА дорогих лайка
пары молча — пуша второму нет, пара снова видна друг другу в пулах и может
лайкнуть заново; потраченные слоты не возвращаются (траты ведутся отдельным
журналом like_spends, §11). Гонка одновременных взаимных лайков не должна
создавать дубль мэтча (транзакция/уникальный индекс).

Правила жизни лайка: дорогой лайк сгорает ровно в двух случаях — удаление
мэтча и блок пары (§5); ни выход из пула, ни изменение точки, ни закрытие
поиска его не трогают. Терминальные состояния лайка: мэтч, удалённый мэтч
или вечное ожидание ответа. Мэтч
постфактум валиден (вышел из пула — взаимный ответ позже всё равно даёт
мэтч; контекст в саммари исторический: «пересеклись на Арбате» — зона в предложном падеже, слова «пул» в UI нет). Вместо
гашения — прозрачность: если у лайкнувшего сейчас нет активных поисков,
его плитка в «Лайках» несёт серую пометку «сейчас не в поиске» — адресат
сам решает, отвечать ли. Потраченный слот досрочно не возвращается
ничем — только истечением своих 24 часов.

Входящие лайки: вкладка «Лайки» (бейдж ждущих ответа на табе) — плитки
с именем и фото сразу, бейджем зоны или «на твою комнату» и ✓-чипами
совпавших параметров лучшей пары, сортировка по совпадению. Тап — анкета
лайкнувшего (открыта по отношению «он меня лайкнул»): сердце «взаимно» →
мэтч (бесплатно), стрелка «отклонить» → пропуск на 7 дней (§2.1), лайк не
сгорает. Чужие дорогие лайки
не видны никому, кроме адресата: ни счётчиков «его лайкнули N», ни публичных
нулей.

## 3. Жизненный цикл поиска

- Создание — форма «Найти», входы: «Соседи» без поиска, «ГДЕ УЖЕ ИЩУТ»
  (зона предзаполнена), «Создать ещё» в «Поисках», финал онбординга — один
  компонент параметров. Кнопка — «Сохранить и смотреть»: подбор без
  подписки не существует (§2.1), сохранение и есть вход. Изменение параметров — свободное
  (пул виртуален, никого не дёргает); лайки не затрагиваются (§2.3).
  ЗОНА ИММУТАБЕЛЬНА: зона — идентичность подписки (на ней держатся свежесть
  в пуле, бейдж «M новых» и пуши), смена зоны = новый поиск; форма нового
  может предзаполняться параметрами старого.
- TTL: «Всё ещё ищешь?» — 7 дней без активности (активность = заход в
  приложение, правка, ответ «Да, ищу»; searches.last_active_at) ИЛИ 3 дня
  после мэтча; молчание 3 дня → пауза (скрыт из пулов, пуши по поиску стоят).
  «Нашёл» закрывает с found_here. Реактивация сбрасывает вопрос.
- Закрытие — с причиной: «нашёл здесь» (ГЛАВНАЯ МЕТРИКА) / «нашёл в другом
  месте» / «передумал». Закрытый поиск реактивируется кнопкой из «Моих поисков».
- Пуш-подписка: активный поиск = подписка на «появился новый совпавший в твоей
  зоне» (см. §7).

## 4. Анкета пользователя (онбординг)

Регистрации нет — вход по Telegram (initData). Онбординг = 12 шагов, ~2 мин.
Анкета выверена по ресерчу предикторов конфликтов сожителей (чистота, сон,
шум, гости/партнёр, деньги — сильные; хобби, психотипы, температура — не
предсказывают и в анкету не входят):

Дословные формулировки (микрокопию не «улучшать» при сборке):

0. Базовое: имя из TG; возраст (число); пол; «С кем готов жить?» →
   «С любым полом» / «Только свой пол». Подпись: «Это взаимно: если ты
   „только свой пол", другой пол тебя не увидит нигде».
1. «Чем занимаешься?» → «Учусь» / «Офис» / «Гибрид» / «Удалёнка» /
   «Сменный график» / «Не работаю». Подпись: «График занятости — это про
   то, когда квартира пустая».
2. «Когда ты активен?» → «Сова — поздно ложусь» / «Жаворонок — рано
   встаю» / «Плавает». Подпись: «Разный график — конфликт номер один
   у соседей». (Про время, не про звук — звук в шаге 5.)
3. «Куришь? (вейп и айкос тоже считаются)» → «Не курю» / «На балконе
   или улице» / «Дома».
4. Животные, два подвопроса на одном экране: «Свои животные?» → «Нет» /
   «Кот» / «Собака» / «Другое»; «Как к чужим?» → «Ок» / «Аллергия» /
   «Против».
5. «Какой звук дома норм?» → «Нужна тишина» / «Нормально» / «Сам шумный».
   Подпись: «Наушники или колонки — вот про это». (Про звук, не время.)
6. «Как часто у тебя гости?» → «Редко» / «Иногда» / «Часто» / «Партнёр
   регулярно ночует». (Партнёр — отдельный вариант: «наполовину живущий»
   партнёр — топ-конфликт сожителей.)
7. «Как у тебя с уборкой?» → «По расписанию» / «Убираю, когда грязно» /
   «Творческий беспорядок».
8. «Алкоголь дома?» → «Не пью» / «С соседом за сериалом — да» /
   «Тусовки — норм».
9. «Как делить общие расходы — коммуналку, бытовое?» → «Поровну и сразу» /
   «Записывать траты (Splitwise и т.п.)» / «Разберёмся по ходу». Подпись:
   «Деньги — вторая причина конфликтов соседей после уборки». Дохода не
   спрашиваем. (Коды значений прежние: split_equally/tracked/as_we_go.)
10. «О себе» — свободное поле до 200 знаков со счётчиком. ЕДИНСТВЕННЫЙ
    свободный текст во всём продукте. Подпись: «Диета, религия,
    температура в комнате — если важно, напиши здесь. Пройдёт проверку
    вместе с фото».
11. «Фото» — до 5, первое — главное (обложка карточки подбора); сетка с
    добавлением, удалением и перетаскиванием порядка. Обязательно хотя бы
    одно, с лицом; валидация — глазами модератора (никакого face-detection
    на MVP), вердикт один на НАБОР целиком — отдельные фото не помечаются.
    Аватар из Telegram НЕ
    подставляем: он может быть скрыт настройками приватности, поэтому путь
    «оставить как есть» работал бы не у всех и требовал бы ветки «а если
    аватара нет».

В анкете НЕТ бюджета/района/дат — это параметры поиска, не личности. Нет
предпочтений о соседе, кроме пола. Каждый вопрос — с подписью, зачем спрашиваем.
Финал онбординга — экран-развилка: галочка «Анкета готова» + плашка проверки
одной строкой («Уйдёт на быструю проверку — виден станешь после» + мелко
«пока можешь смотреть и сохранять поиски, лайки сохранятся»); затем ДВЕ
карточки-пути в цветах типов, обе тапабельные: розовая главная «Ищу, куда
съехать» («Настрой поиск — 20 секунд, покажем людей и квартиры» → форма
«Найти») и зелёная «Зову соседа к себе» («Уже живёшь в квартире или
заезжаешь — найди, кто въедет» → форма «к себе»); под ними тихая ссылка
«просто посмотреть».

Пол — единственное серверное обоюдное правило видимости: при несовпадении
gender_pref люди друг для друга НЕ СУЩЕСТВУЮТ нигде (пулы, счётчики, пуши,
лайки, «тебя лайкнули»). Реализуется в ЕДИНОЙ функции/запросе видимости
visible_people(viewer_id, ...), через которую ходят ВСЕ потребители (зонный пул,
квартирный пул, счётчики, пуши, валидация лайка). gender_pref NOT NULL DEFAULT
'any'. Счётчики из-за этого персональные. Блокировки (blocks) — та же проверка.

## 5. Модерация и доверие

- Статусы анкеты: **draft** (аккаунт создан первым запуском, анкета не
  дозаполнена — регистрации нет, §4) → **pending** (отправлена, ждёт
  модератора) → **active** (одобрена, видна везде). Отдельно **banned** —
  исход разбора жалобы. В draft и pending права одинаковые: МОЖНО листать
  подбор и пропускать, создавать поиски; НЕЛЬЗЯ быть видимым
  другим и ставить дорогие лайки. После аппрува человек «проявляется» везде
  разом. Разделение draft/pending обязательно: в очередь модерации попадают
  только отправленные, черновик продолжают с брошенного шага, и микрокопия у
  них разная («заполни анкету» против «анкета на проверке»). Определять
  готовность по «все поля анкеты не NULL» нельзя — предикат придётся повторять
  в каждом запросе и переписывать при добавлении вопроса.
- Модерация ручная, в отдельном ТГ-чате основателя (MODERATION_CHAT_ID;
  пусто — очереди копятся, команда /queue в чате досылает накопленное), две
  очереди: анкеты (фото + «о себе»: ок / фото не ок / текст не ок) и
  пользовательские точки (ок / отклонить; для «к себе» дополнительно: фото
  комнаты не стоковое, цена доли адекватна рынку). Вердикты идемпотентны:
  тап по устаревшей кнопке — «уже обработано», одобрить можно только то, что
  сейчас в очереди (стухшая кнопка «ок» не воскрешает отклонённое). Любой
  вердикт по забаненному — no-op: «забанить» — исход разбора жалоб
  (скам/угрозы), не инструмент модерации контента, и разбаниваться тапом по
  старой кнопке нельзя. Поиски НЕ модерируются (структурные, текста нет).
- Реджект фото ≠ бан, но и не «виден с оговоркой»: фото ОБЯЗАТЕЛЬНО (§4,
  шаг 11), поэтому анкета с отклонённым фото возвращается в **draft** и
  пропадает из выдачи до перезагрузки фото. Причина остаётся в photo_status =
  rejected, уходит пуш «Фото не подошло — загрузи другое, где видно лицо»
  с диплинком на шаг фото (ответы сохранены); та же строка стоит на своём
  профиле — draft после реджекта в онбординг не запирается. Статуса «без
  фото» НЕТ — он противоречил бы обязательности фото. «О себе» отклоняется
  тем же путём («Текст „о себе" не подошёл — поправь его» → шаг «о себе»).
- Редактирование одобренной анкеты: на перепроверку уходят ТОЛЬКО фото и
  «о себе» — ровно то, что модератор смотрит. Привычки, возраст, занятость
  меняются молча: правка «сова → жаворонок» не должна выкидывать человека из
  пулов. Статус пользователя при этом НЕ меняется, он остаётся **active**;
  сбрасывается только photo_status / about_status в pending. Карточка
  модератору уходит НЕ при сохранении поля, а по кнопке «Отправить на
  проверку» в конце правки — одна на фото и текст вместе (как у черновика:
  сохранение ≠ отправка; брошенную правку досылает /queue). Пока фото не
  одобрено — вместо него ЗАГЛУШКА, пока не одобрено «о себе» — блок не
  показывается вовсе. Теневых копий полей нет. На перепроверку набор уходит только при
  ДОБАВЛЕНИИ фото (нового контента); удаление и перестановка одобренных
  фото статус не трогают. Статус один на весь набор — отдельные фото не
  помечаются; если пополненный набор отклонили, заглушка стоит до
  следующей правки.
  Отсюда ДВЕ ветки реджекта фото: у не прошедшего проверку ни разу — возврат
  в draft (выше), у активного — статус не трогаем.
- Точка создателю видна сразу (статус «на проверке»), в подбор — после
  аппрува. Автовалидация до модератора: цена доли 20–300к, метро из
  справочника, описание ≤400.
- Верификация почтой — ОПЦИОНАЛЬНАЯ (не гейт): домен вуза → бейдж (вайтлист
  доменов в конфиге, старт — 2–3 вуза), позже корп-домены той же механикой.
  Лейбл по занятости: «учебная» студенту, «рабочая» работающему. Всегда бесплатна.
- Блок: кнопка в профиле или в деталях мэтча → строка в blocks → обоюдная
  невидимость немедленно (та же проверка visible_people, §4); в той же
  транзакции стираются мэтч пары (если был), оба лайка и ответы опроса;
  `liked`-пуши пары и pending-пуши мэтча гасятся. Идемпотентен;
  разблокировки нет ни в API, ни в UI. После блока профиль цели отвечает 404
  как невидимый.
- Жалоба: кнопка в профиле → причина чипом (спам/реклама, мошенничество,
  оскорбления/угрозы, другое) → строка в reports с контекстом (зона, точка
  или мэтч) → карточка ТЕМ ЖЕ ботом в MODERATION_CHAT_ID рядом с очередями
  анкет и точек, кнопки «Забанить» / «Пропустить». Отдельного саппорт-бота
  нет. Повторная жалоба той же пары карточку не дублирует (UNIQUE на пару).
  Жалоба НЕ блокирует автоматически: разбор нужен модератору, невидимость —
  пожаловавшемуся, поэтому после отправки UI отдельной кнопкой предлагает
  «Заблокировать». «Забанить» → status='banned' (идемпотентно, забаненный —
  no-op), его pending-пуши гасятся, все его незакрытые точки (pending/
  active/paused) закрываются с причиной rejected — скам-ссылка не должна
  висеть в ленте, — вход в приложение закрыт; «Пропустить»
  закрывает жалобу без последствий. Нерешённые жалобы досылает /queue.
- Бан пира НЕ стирает мэтч из списков, но контакты в деталях мэтча
  скрываются — «Контакт недоступен». Блок пары мэтч удаляет (выше).
- (Пост-MVP: редактирования точек в MVP нет, см. §7/§11.) Существенное
  изменение точки (цена, зона, комнаты) → пуш пулу с дельтой («90к → 110к»);
  лайки не затрагиваются. Косметика — молча.

## 6. Экраны

Табы: **Соседи / Лайки / Поиски / Профиль** (бейдж входящих лайков, ждущих
ответа, на «Лайках», бейдж новизны на «Поисках»). Вёрстка и микрокопия — макет
https://claude.ai/code/artifact/2271b036-3b81-4523-892e-cde93c079a53,
страница «Подбор · светлая» (тёмная — токены темы, уже в tokens.css).

- **Соседи (подбор)**: шапка «Соседи · N в твоих зонах» + иконка фильтров;
  одна карточка на экран. Карточка человека: фото на весь верх (до 5,
  сегменты-пейджер, тап по краям листает), бейджи на фото — зона лучшей
  пары («Арбат · твоя зона» при равной/вложенной) и «совпали по всем
  параметрам» (при полной секции); на градиенте — «Имя, возраст»,
  «Занятость · был(а) сегодня»; ниже вердикт-чипы его параметров и строка
  привычек. Карточка комнаты — §2.2. Тап по карточке — полная анкета
  (комната — экран комнаты; строка автора — его анкета). Под карточкой две
  кнопки-иконки: стрелка = пропустить, сердце = дорогой лайк («Хочу эту
  комнату» у комнат); под ними пять точек — остаток лайков, без текста.
  Свайпы дублируются кнопками (порог ~35% ширины, без библиотек).
- **Соседи, состояния.** Без поиска: «С кем будешь жить?» + подпись +
  «Найти», карточка «Как это работает» (1 «Сохрани, где ищешь» / 2 «Свайп
  вправо — „хочу жить вместе“» с «влево — пропустить, вернём через
  неделю» / 3 «Ответный лайк открывает контакты») и «ГДЕ УЖЕ ИЩУТ» (топ-5
  зон, тап → форма с зоной). Конец подбора: «Пока все» + «Показать
  пропущенных · N» + «Сохранить ещё поиск · слот K из 3». Анкета на
  проверке: жёлтая плашка «Анкета на быстрой проверке — смотреть и
  пропускать можно уже сейчас. Лайк откроется после одобрения — тебя тоже
  станет видно», сердце серое (стрелка работает).
- **Фильтры** — шторка «Каким должен быть сосед» (пометка «пусто =
  неважно»): «Кого показывать» (Ищут соседа / Зовут к себе), «Возраст»
  от–до, «Животные в квартире» (Без животных / Не против моих), «Курение»
  (Не курит совсем / Не курит дома), «Режим дня» (Сова / Жаворонок), «Чем
  занят» (Учится / Работает / Не работает); мультивыбор; кнопки
  «Сбросить» и «Показать · N» с живым счётчиком.
- **Лайки** — плитки 2 в ряд: фото с бейджем «ищет: {зона}» (розовый) или
  «на твою комнату» (зелёный + зелёная рамка плитки), «Имя, возраст» на
  градиенте, под фото ✓-чипы совпавших параметров. Без вводных подписей.
  Тап — анкета лайкнувшего («лайкнул(а) тебя» в подзаголовке), внизу
  стрелка (отклонить) и сердце (взаимно) + подпись «Сердце — взаимный
  лайк: не тратит лимит и открывает контакты». Пустое состояние: «Пока
  никто не лайкнул. Появись в подборе — сохрани поиск».
- **Форма поиска («Найти»)**: зона обязательна, бюджет-вилка, наборы
  комнатности/заезда/срока чипами (подписи из шага 10); кнопка «Сохранить
  и смотреть» (на зоне с уже существующим активным поиском — обновляет
  его, как раньше).
- **Поиски**: (1) «Мои поиски» до 3 карточками — чипы параметров, «N ищут
  соседа · с K полное совпадение», бейдж «M новых», кнопка «Смотреть в
  „Соседях“», «Изменить · Закрыть», реактивация из архива, «Создать ещё»
  с остатком слотов; пуши «новый ищущий» диплинкают в «Соседей». (2)
  «Зову к себе · N из 2» — как раньше: стадия-бейдж, «N откликов»,
  закрытие с причиной, «Скрыть», пустое состояние «Живёшь в квартире или
  заезжаешь — найди соседа». Блоков рыночных квартир НЕТ.
- **Анкета человека** (полная), **мэтч**, **профиль свой**, **анкета
  (редактирование)** — как в шаге 10, с правками: шторки блока и удаления
  мэтча говорят «в подборе» («Вы перестанете видеть друг друга везде — в
  подборе, лайках и пушах», «…снова увидите друг друга в подборе»); фото —
  сетка «Фото ·
  N из 5» (большое главное с меткой «главное», крестики на остальных,
  слоты «+», одна жёлтая метка «уйдут на проверку» на блок, подпись
  «Первое — главное, его видят в подборе. Зажми и перетащи, чтобы поменять
  порядок. Новые фото уйдут на проверку»); тот же
  грид — шаг фото онбординга. «Тебя лайкнули» из профиля УБРАНО — живёт
  вкладкой «Лайки»; «Мои мэтчи» в профиле остаются.
- **Экран комнаты** (тап по карточке или диплинк `point_<id>`) — те же
  блоки, что карточка §2.2, плюс «✓ У вас мэтч» при мэтче; у автора кнопки
  нет.

## 7. Уведомления (через бота)

Пуш = строка в логе notifications (пишется best-effort после коммита
доменной операции) + фоновый воркер в api (тик 30 с), который шлёт через
бота: личные — сразу, агрегируемые — одним сообщением на (юзер, контекст)
не чаще раза в 24 ч. Общего rate-limit «N в день» НЕТ — пороги точечные.
Тексты короткие, без деталей и совпадений — детали в приложении по кнопке
(web_app-кнопка с диплинком `startapp=`).

Типы и тексты (дословно):
- `zone_new` — сохранение/реактивация поиска: всем со-пульникам (активный
  поиск, пересекающий зону; visible_people; минус автор и смэтченные),
  агрегат по зоне поиска подписчика: «В Хамовниках ищут квартиру ещё 4
  человека» / «…ищет квартиру ещё один человек» → «Открыть подбор». Автор в
  pending строк не рождает; при аппруве анкеты его активные поиски
  доанонсируются.
- `pool_new`, `point_gone` — МЕРТВЫ вместе с рыночными квартирами
  (этап 1): код заморожен, новые строки не пишутся.
- `point_ping` — 7 дней без подтверждения жизни (§8), только автору
  «к себе»: «Комната у метро Сокол ещё свободна?» `[Да] [Нашёл соседа]`
  (колбэки в боте, префикс `pnt:`; «Да» продлевает, второй ответ закрывает
  с found). Вопрос, а не событие: в предохранитель личных не считается.
- `liked` — тратящий лайк: «Тебя лайкнула Катя» (род из анкеты, без
  контекста) → «Посмотреть»; при ≥10 личных за 24 ч сворачивается в хвост
  «И ещё 4 лайка за сегодня» (редактируется последнее сообщение).
- `matched` — «У тебя мэтч!» → «Открыть»; никогда не сворачивается.
- Вердикты модерации: «Анкета прошла проверку — теперь тебя видно» / «Фото
  не подошло — загрузи другое, где видно лицо» / «Текст „о себе" не подошёл
  — поправь его» / «Твоё объявление одобрено / отклонено» → диплинки в
  подбор / шаг фото / шаг «о себе» / «Поиски».
- `still_searching` — «Всё ещё ищешь в Хамовниках?» с кнопками
  `[Да, ищу] [Нашёл]` (колбэки в боте, «Нашёл» закрывает с found_here);
  `post_match` — «Как дела с Катей? Расскажи, что вышло»
  `[Съезжаемся] [Общаемся] [Не сложилось]` (ответы — метрика в match_polls,
  без наград). См. §3.
Не в MVP: «точка изменилась» (редактирования нет).

Ошибки доставки: бот заблокирован / чат не найден → users.push_blocked_at,
очередь юзера гасится, новые события ему не пишутся; любое личное сообщение
боту снимает блок. Прочие ошибки — ретрай, после 5 попыток строка failed.
Уникальный индекс (адресат, тип, актор, контекст) — дубли невозможны на
уровне БД; в приложении реалтайма нет — по кнопке пуша всё перечитывается.

## 8. Контент и лимиты

- Рыночные квартиры ВЫКЛЮЧЕНЫ (этап 1): сервис parser не поднимается
  (docker-compose `profiles`), точки type=flat закрыты разово при выкатке
  (`close_reason closed`), дешёвый лайк, пулы квартир, голоса свежести и
  их пуши не работают. Код парсера и конвейера свежести, таблицы
  channel_posts / point_votes / likes_points — заморожены до этапа 2
  (§9): не развивать и не вычищать.
- «К себе»: пинг автору раз в 7 дней от последнего подтверждения жизни,
  TTL — 14 дней без подтверждения или 3 дня молчания после пинга →
  closed/expired, реактивации нет. Подтверждение жизни — создание, «Да» на
  пинг, мэтч с точкой в контексте.
- Лимиты: поисков ≤3 (зоны могут пересекаться, §2.1); «к себе» — live 1,
  moving_in ≤2, суммарно ≤2; дорогих лайков — 5 слотов, окно 24 часа;
  «о себе» ≤200 знаков; описание комнаты ≤400; фото анкеты ≤5; фото
  комнаты ≤10.
- Справочник зон: станции, ветки, районы Москвы; зона → множество станций;

## 10. Стек и архитектура

- **Бэк**: Go, структурированный монолит: доменные пакеты (users, searches,
  points, pools, likes, matches, notifications, moderation), тонкие слои
  handler → service → storage; интерфейсы на границах слоёв — всегда, объявлять
  на стороне потребителя. SQL руками через pgx (без ORM). PostgreSQL. Валидация
  TMA initData (HMAC). Пуши: Bot API sendMessage. Правило видимости — одна
  точка (visible_people), какой бы пакет её ни вызывал.
- **Парсер**: отдельный сервис на Python (httpx + BeautifulSoup, psycopg,
  anthropic), общается с бэком только через БД. Транспорт — HTTP-поллинг
  веб-превью каналов (лента t.me/s, живость поста через embed); MTProto на
  MVP нет, за швом fetch он — отложенный апгрейд. LLM-структуризация поста —
  claude-sonnet-5 со structured outputs.
- **Фронт**: React + TypeScript + Vite. @telegram-apps/sdk-react (initData,
  тема, MainButton/BackButton), @telegram-apps/telegram-ui. Цвета — переменные
  темы Telegram; кастом — только шапки типов карточек и акцентная кнопка.
- **Инфра**: один VPS, docker compose (api, parser, postgres), Caddy (HTTPS
  обязателен для TMA), фронт — статика. Без k8s/redis/очередей.
- **Прод**: flatmatch.ru, VPS с репозиторием в /opt/flatmatch, стек тем же
  docker compose (postgres, api, parser, caddy), сертификат — Caddy +
  Let's Encrypt, ssh по алиасу `flatmatch`. Код — приватный GitHub
  `rococo4/flatmatch` (origin, с Мака по HTTPS), `/opt/flatmatch` — его клон
  по read-only deploy-ключу. Выкатка — `scripts/deploy.sh`: проверяет, что
  локальный main запушен, на сервере `git reset --hard origin/main` +
  `docker compose up -d --build`; бэкап —
  `scripts/backup.sh` на сервере (pg_dump в /opt/flatmatch/backups, хранить
  7 дней, крон 04:00). Миграции применяет api на старте. Секреты живут
  ТОЛЬКО в серверном .env: он вне git, выкатка его не трогает, в репозитории
  и в документации значений нет. CI нет — деплой руками с машины. Детали и
  восстановление машины — README, раздел «Деплой».
- **Модерация**: тот же бот, отдельный чат основателя, inline-кнопки; там же
  третья очередь — жалобы (§5).
