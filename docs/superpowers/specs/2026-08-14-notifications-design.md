# Пуши — дизайн (§12 шаг 6)

Дата: 2026-08-14. Статус: дизайн согласован по секциям в брейншторме;
ждёт ревью спеки пользователем перед планом.

Охват: notifications-лог, событийные пуши §7, агрегация зонных и пуловых,
доставка через бота с диплинками, ответы кнопками в боте («ещё ищешь?»,
пост-мэтч опрос), фронт: разбор диплинков и замыкание петли реджекта фото/«о
себе» (§5).

## Решения пользователя

| Вопрос | Решение |
|---|---|
| Доставка | Очередь в БД + фоновый воркер в api. Событие пишется строкой в момент коммита, воркер шлёт. Без redis/очередей (§10) |
| Rate-limit ≤2–3/день из §7 | ОТМЕНЁН как общее правило. Пороги точечные: агрегируемые типы — не чаще 1 пуша на (юзер, контекст) в 24 ч; личные — сразу; предохранитель — сворачивание хвоста, не откладывание |
| «Новый ищущий в зоне» — кому | Только тем, с кем новичок совпал ПОЛНОСТЬЮ или ЧАСТИЧНО (секции пула «совпали по всем» + «пересекаются частично»); «не совпали» — без пуша, только молча в пуле |
| «Новый в пуле точки» | Всем участникам пула (не только первому), агрегат 1/точка/день |
| TTL «ещё ищешь?» | Оставляем в шаге 6 (актуализация поисков) |
| Свежесть объявлений (шторка после перехода, пинг создателю, «похоже, сдана») | Шаг 7, сразу следующий |
| Петля реджекта фото/«о себе» | Замыкаем целиком: пуш + экраны читают photo_status/about_status + диплинк в редактор |

## 1. Схема — миграция 0007_notifications.sql

```sql
notifications (
    id          uuid PK DEFAULT gen_random_uuid(),
    user_id     uuid NOT NULL REFERENCES users(id),   -- адресат
    type        text NOT NULL,                        -- словарь §2 (CHECK)
    actor_key   text NULL,   -- кто вызвал: uuid юзера / точки; дедуп «один актор — одно событие»
    context_key text NULL,   -- ключ склейки агрегата: zone_id подписчика / point_id
    payload     jsonb NOT NULL DEFAULT '{}',          -- имена, флаги совпадения, тексты
    created_at  timestamptz NOT NULL DEFAULT now(),
    sent_at     timestamptz NULL,
    failed_at   timestamptz NULL,
    attempts    int NOT NULL DEFAULT 0
);
CREATE UNIQUE INDEX notifications_actor ON notifications (user_id, type, actor_key)
    WHERE actor_key IS NOT NULL;                    -- дубли невозможны на уровне БД (§7)
CREATE INDEX notifications_queue ON notifications (user_id, created_at)
    WHERE sent_at IS NULL AND failed_at IS NULL;
CREATE INDEX notifications_sent ON notifications (user_id, type, context_key, sent_at DESC)
    WHERE sent_at IS NOT NULL;                       -- окно 24ч по контексту

ALTER TABLE users    ADD COLUMN push_blocked_at timestamptz NULL;  -- бот заблокирован
ALTER TABLE searches ADD COLUMN last_active_at timestamptz NOT NULL DEFAULT now(),
                     ADD COLUMN ttl_asked_at   timestamptz NULL;   -- «ещё ищешь?» задан

match_polls (match_id uuid, user_id uuid, answer text
    CHECK (answer IN ('moving','talking','failed')), answered_at timestamptz,
    PRIMARY KEY (match_id, user_id));                -- метрика, в UI не показывается
```

`last_active_at` двигают: открытие приложения (любой авторизованный запрос —
раз в час, не на каждый), правка поиска, ответ «Да, ищу». `sent_at` — единая
отметка «пуш ушёл», по ней считаются и окно агрегата, и предохранитель.

## 2. Типы

| type | Триггер (Emit) | Адресаты | Режим | Текст | Кнопка → startapp |
|---|---|---|---|---|---|
| `zone_new` | создание/реактивация поиска (searches) | активные поиски, пересекающие зону, × visible_people, минус автор, минус смэтченные, минус секция «не совпали» (pools.Compare) | агрегат, context = зона поиска подписчика; ВСЕГДА число, именной формы нет | «В Хамовниках 4 новых ищущих» (1: «В Хамовниках новый ищущий») | «Открыть пул» → `pool_<zone>` |
| `pool_new` | Enter в пул flat (points) | участники пула минус вошедший, × visible, минус смэтченные | агрегат, context = point_id; всегда число | «+2 в пуле квартиры у м. Фрунзенская» | «Открыть пул» → `point_<id>` |
| `liked` | тратящий лайк (likes) | адресат | сразу; хвост при >10 личных/24ч | «Тебя лайкнула Катя» / «Тебя лайкнул Марк» (род — из анкеты); без контекста; хвост: «Ещё 4 лайка сегодня» (editMessageText, а не новое) | «Посмотреть» → `incoming` |
| `matched` | рождение мэтча (likes) | оба | сразу, НИКОГДА не хвостуется | «Это мэтч» | «Открыть» → `match_<id>` |
| `profile_ok` | mod:u:ok | юзер | сразу | «Анкета одобрена — ты виден в пулах» | «В ленту» → `feed` |
| `photo_rejected` | mod:u:photo | юзер | сразу | «Фото не прошло проверку — загрузи другое, с лицом» | «Загрузить» → `photo` |
| `about_rejected` | mod:u:about | юзер | сразу | «Текст „о себе" не прошёл проверку — поправь» | «Поправить» → `about` |
| `point_ok` / `point_rejected` | mod:p:ok / no | создатель | сразу | «Твоё объявление одобрено» / «Твоё объявление отклонено» | → `mine` |
| `still_searching` | воркер: 7 дней без активности ИЛИ 3 дня после мэтча, ttl_asked_at пуст или старше окна | владелец поиска (searches.user_id) | 1/поиск/окно; молчание 3 дня → пауза поиска | «Ещё ищешь в Хамовниках?» | `[Да, ищу]` `srch:yes:<id>` · `[Нашёл]` `srch:found:<id>` (закрывает с found_here) |
| `post_match` | воркер: 5–7 дней после мэтча | оба | 1/мэтч/юзер | «Поделись, как сложилось с Катей» | `[Съезжаемся]` `[Общаемся]` `[Не сложилось]` → `poll:<match>:<answer>` |

Не в скоупе: «точка изменилась» (редактирования нет), «квартира, похоже,
сдана» и пинг создателю (шаг 7). Совпадения считает только фан-аут `zone_new`
(кому слать), в текст они не попадают — «усиленная формулировка» §7 снята:
тексты короткие, детали — в приложении по кнопке.

Пол/бан/блок — через visible_people при Emit (мёртвый адресат не получит
строки), и повторно при отправке (адресат мог быть забанен между).

## 3. Emit — сервис notifications

`Emit(ctx, Event{Type, UserID, ActorKey, ContextKey, Payload})` — best-effort
после коммита доменной операции (как модерация): ошибка — warn в лог, продукт
не падает. INSERT `ON CONFLICT DO NOTHING` по actor-индексу. Fan-out типов
`zone_new`/`pool_new` делает сам сервис notifications через потребительские
интерфейсы (Searches: подписчики зоны; Points: участники пула; Pools:
Compare для секции) — доменные сервисы зовут одну строку `EmitZoneNew(search)`.
`users.push_blocked_at NOT NULL` → адресат пропускается при Emit.

## 4. Воркер

Горутина в api (рядом с ботом), тик 30 с, один инстанс (VPS один; на будущее
— pg advisory lock на проход). Проход:

1. Личные типы: все неотправленные строки, поштучно, по возрастанию created_at.
   Предохранитель: если у юзера за 24 ч ≥10 отправок личных — `liked`
   сворачивается в хвост (одно сообщение с числом, редактируется), сервисные
   и `matched` идут как есть; хвост нечем собрать (не liked) → warn в лог.
2. Агрегируемые: группировка (user, type, context_key); если по контексту
   была отправка <24 ч назад — ждут; иначе одно сообщение с числом, все
   строки группы получают один sent_at.
3. Раз в час: TTL-скан поисков (still_searching), пост-мэтч (post_match),
   пауза поисков с неотвеченным вопросом старше 3 дней (status → paused).

Отправка: `sendMessage(chat_id = tg_id)` с inline-кнопкой (`web_app`-кнопка с
`APP_URL?startapp=…` для диплинков; `callback_data` для ответов). Успех →
sent_at; временная ошибка → attempts++, ретрай следующим тиком, attempts ≥5 →
failed_at; «Forbidden: bot was blocked» / «chat not found» → users.push_blocked_at
+ все его pending → failed_at.

Колбэки в боте: маршрутизация по префиксу — `mod:` (только модерационный
чат, как есть), `srch:` и `poll:` (личка): владелец проверяется по данным
(searches.user_id / участник мэтча = tg_id тапнувшего), чужой → «не твой»,
повтор → «уже ответил», кнопки → метка ответа (как у модерации).

## 5. Фронт

- `startapp` словарь: `point_<uuid>` (есть), `pool_<zone>` (нет своего поиска
  зоны → лента с этой зоной), `incoming`, `match_<uuid>`, `mine`, `photo`,
  `about`, `feed`. Разбор при старте до первого рендера.
- Профиль читает `photo_status`/`about_status` из `/me`: draft после реджекта
  — строка «Фото не прошло проверку — загрузи другое, с лицом» → шаг фото
  онбординга (ответы сохранены); active с rejected — заглушка вместо фото + та
  же строка → редактор; «о себе» rejected — блок скрыт + «поправь»; pending у
  active — «новое фото на проверке» под заглушкой.
- Реалтайма нет: открытое приложение узнаёт о новом при следующем стартовом
  фетче/возврате по кнопке пуша.

## 6. Тесты

- notificationsrepo: дедуп по актору (второй Emit того же актора — 0 строк),
  окно 24ч по контексту, очередь по индексу.
- service: fan-out zone_new (подписчик в «не совпали» не получает строки;
  смэтченный не получает; невидимый по полу не получает; автор не получает),
  pool_new (вошедший не получает), тексты 1/N, хвост liked.
- воркер на фейковом Sender с управляемыми часами: агрегация, окно, ретраи и
  failed после 5, блокировка бота, предохранитель, TTL-скан и пауза по
  молчанию, идемпотентность колбэков.
- httptest: колбэк «Нашёл» чужого поиска → «не твой», без записи.
- Приёмка: реальные пуши в личку пользователя (188993596) на стенде: лайк от
  Дева → пуш; мэтч → пуш; сохранение поиска сидом → агрегат; «ещё ищешь?» с
  подкрученным last_active_at → кнопки → пауза/закрытие.
